# Investment Studio — Watchlist

Watchlist 承载观察池、单资产研究、监控和本地物化 read model。当前主路径支持 `public_fund / private_fund / etf / equity / index / crypto`；其他 Instrument Data 类型不会被塞入通用详情页。

## 职责与边界

- `Watchlists`：名单、view、筛选、排序、分组和导出；
- 自定义观察列表可在入口菜单或列表设置中重命名，保留原 ID、成员和视图；
- 管理员与协作成员可创建共享列表，所有成员均可见，只读成员不能修改；列表卡片和设置显示创建人，旧列表未记录的创建人保持未知；
- `Instrument Detail`：按资产类型进入基金、ETF、股票、指数或加密资产现货工作面；
- 投资观点：PM 的投资判断、逐条研究笔记和修订历史；
- 投资研究：专属研究员的资料档案、持续底稿、当前结论、重要风险机会与后续进展；
- 研究助手：各页面可打开的上下文对话抽屉，读取研究档案和风控结论，支持提问、上传证据和共同样本比较；
- 标的风险：复核线、自动观察、人工事项和持续跟进；Portfolio 复用同一套记录；
- `Monitoring`：来源新鲜度、字段缺失、重算状态和复核到期；
- `Recalculation`：从 Instrument Data canonical facts 构建 Watchlist-local snapshots 和 rows。

Watchlist 直接读取 `instrument_data` 共享事实和 `data_ingestion` 的公开证券目录，不直接修改 canonical identity、quote/NAV/FX 或 corporate actions。列表添加并行查询已登记资产和市场证券目录；已登记资产通过一次身份查询跨全部支持类型检索，不逐类型请求完整行情档案；用户明确添加未登记股票或 ETF 时，经共享证券桥接调用 `investment-studio data` 的登记与行情刷新命令，再加入列表。搜索不登记资产，目录缺失或失败保留提示，批量文件添加仍只匹配已登记标的。其余行情导入、修订和刷新由同一数据维护入口负责。Watchlist taxonomy、研究事实、名单和 read model 只写入 `watchlist` schema，不进入共享资产数据或 Portfolio。

关键运行约束：

- 系统名单为 `全部标的 / Index / All 公募 / All 私募`；全部标的自动收录有效登记且有 Watchlist 工作面的资产，自定义名单只组织成员；打开或切回列表页面时先同步成员及数量，再更新行数据，保留当前筛选和视图；
- 首屏并行读取目录、字段和保存视图；分类选项不阻塞主表，筛选值在打开菜单时按需加载。主要页面加载使用居中悬浮提示；切换名单时取消旧请求，迟到结果不覆盖当前页面；
- 当前路由的页面代码与会话校验并行下载，业务页面及数据请求仍等待授权。列表和详情不提前下载未打开的研究助手；列表风险抽屉也在打开时加载，加载反馈沿用居中悬浮提示；
- 每个 instrument 使用自己的 calculation-series as-of，名单不伪造共同计算日；
- 混合资产名单只暴露对全部当前类型都有定义的字段；
- Group By 只组织视图，不隐式修改 taxonomy 或研究事实；
- 系统默认视图平铺资产，分类与研究阶段作为列；用户保存的分组视图保留；
- canonical recalc 只消费 Instrument Data 中符合 status、currency 和 quote policy 的观测；条件不足时结果为 unavailable；
- Instrument Data 通知用于降低延迟，不是正确性边界；durable worker 会主动对账 source generation；
- 列表使用与完整图表同次发布的紧凑投影，预先计算现有 `1D / 1W / 1M / 1Y` 四个走势窗口；详情保留完整历史。窗口计算、收益口径和来源时点一致，列表请求不读取完整历史再裁切；当前列菜单仍只开放 `1M` 走势；
- 收益、风险和 benchmark 只在合同规定的端点、共同样本及 return semantics 下发布，不做静默回退。

Watchlist schema `20260920_0059` 新增列表图表投影。统一发布流程须先停写、备份并迁移，再执行 `backend/scripts/refresh_release_watchlists.py`，为包括归档资产在内的既有图表补齐投影；该补齐只派生已存图表，不获取行情，也不推进原来源时点。`audit_live_data.py` 的 `watchlist_screener_projection_ready` 检查通过后才可恢复服务与调度。运行时若投影缺失，列表明确返回暂不可用并持久化入队修复，worker 对账也会发现缺口；不在页面请求中现场重算。字段与升级合同见 [数据模型与 API](./docs/DATA_MODEL_AND_API.md#45-read-models)。

## 投资观点、投资研究与研究助手

ETF、股票、指数和加密资产现货详情页使用“总览 / 投资研究 / 投资观点 / 业绩与风险”；公募和私募另有“基金档案”。投资观点保存 PM 自己的研究判断与历史，原研究资料可只读展开。投资研究是一份连续的专业报告：投资结论、适配底层暴露的回报机制与定价分析、量化与风险、主题与事件共用同一份研究；依据与历史档案收在报告附录。页内目录负责定位，不再把概览和深度报告分成两个阅读模式。摘要呈现完整的当前判断、吸引力、反证和验证重点；正文按适用投资机制展开：经营、成份、供需、策略、利率信用、网络经济等章节由实际研究方法决定，不依据产品名称套模板；只把已有分析作为章节，不用空白方法模板充当报告。量化图表来自同一底稿的留存数值，主题跟踪与重要事件是报告中的持续验证章节。最近一轮失败原因直接显示在研究区，已有观点保留其原始更新时间；失败尝试不冒充研究更新。研究助手从各页面打开对话抽屉，读取当前页面和所选标的上下文，不占用独立详情 tab。投资研究和助手共用持续研究档案、工具与正式更新路径。用户明确要求分享的对话研究成果通过同一核证流程回到投资研究，个人讨论留在对话；PM 投资观点由用户决定采用和修改。

分析方法按研究对象和问题选择，不设置统一的宏观或催化剂流程。股票侧重经营、竞争、财务和估值；行业侧重供需、产能、技术和利润分配；宽基与大类资产研究相关宏观和跨资产变化；黄金等资产使用自身定价机制。ETF 先辨别底层，再分析实际成分、权重、币种及载体结构。公募与私募开放投资研究和助手；先用可信净值、实际披露频率、策略分类及同类/基准的共同样本开展研究，再随原始材料补充策略、费率、流动性与披露持仓。合同基准、用户比较指数与候选同类分别标明；统计相关性不能还原实际持仓或证明管理能力。持仓报告期、披露滞后和实际资料覆盖必须保留，不能把未披露敞口、杠杆或对冲由净值反推成事实。材料目录没有正文时不能视为已阅读。

列表成员、标的全局设置与研究档案分别保存。移除成员或删除自定义名单不注销资产，不删除投资状态、研究框架、材料、PM观点或风控记录；同一标的出现在多个名单时仍使用同一份设置和档案。全部标的是登记目录，不自动生成目录级风控研判；符合状态条件的成员仍按标的去重研究。归档资产不出现在有效资产目录中，既有研究仍保留。

研究框架支持在页面编辑，保存作者与修订版本；用户重点、明确约束和用户选择的研究领域独立保存，研究员不能覆盖。公共方法库 `data/research/frameworks.json` 由 `research_methods` 按真实登记、底层和策略组合为 `research_plan`，不再把公共正文复制进新专属框架。专属背景、机制、问题和资料计划保存在 mandate；公共方法实质更新提升模块版本，相关旧分析显示待复核。原有标的专属初始补充继续保留，数据库中的已保存版本始终优先。基础方法、来源摘要、历史计算基线和当前研究结论分别标识。AI摘要或历史补建不是独立原始证据，保留其生成时间与原文日期，不能用旧文章日期冒充事前研究。

投资研究页面的首屏与正文来自同一份有版本的 dossier，运行接口仅提供检查状态。`research.modules` 以稳定方法 key 保存摘要、完整分析、来源、资料日期、缺口与单独检查时间；覆盖状态不等于投资评级。整体 `investment_view` 仍是唯一当前研究员判断。Briefing 行业目录和原有 `mode=report` 链接均进入同一报告，不另存研究结论。主题是报告中的持续研究部分，桌面使用主题目录和单主题阅读区，窄屏使用主题切换；当前分析、演变、证据分别呈现。日常演变不默认混入整理回执和引用修正，原始记录仍可展开追溯。重要事件即使已关联主题，也保留在近期事项入口。新提交停止使用 `fundamental_view / valuation_view`，旧快照只通过集中历史读取映射为带原始日期与来源的 `prior_analysis`。模块图表通过 `figure_source_ids` 引用实际留存的数值证据，不接受模型自由生成图表数据。

研究员编制可通过 `backend/scripts/import_research.py` 提交仓库外的原文摘录、数值表格与完整研究包。默认只读预览，发布必须绑定已查看的预览和相同内容；实际调用沿用既有团队授权、标的锁、来源与版本校验。该入口真实记录 Codex 编制、作者来源核对和研究截至日期，不调用或冒充 DeepSeek，不伪造独立模型核证，不写 PM 投资观点，也不改写事件历史。新增原文以作者提供材料独立留存，保留原始链接、发布日期、定位和收录时间，不覆盖同 URL 的系统抓取版本。完整运行合同见[数据模型与 API](docs/DATA_MODEL_AND_API.md)。

每个已登记的支持类型都有研究档案入口，汇集该标的原始材料、适用研究方法、历史案例和最近完成的持续底稿。文字与文件材料复用稳定的 `dossier:{instrument_id}` 研究话题；实际正文、出处、发布日期、资料适用日期与收录时间分别保存。既有基金本地文件可读取文本或 PDF 文字层，缺失、扫描件或不支持格式明确标注；其他标的或组合私有资料不混入。研究方法是问题框架，不是事实依据。

持续底稿按 research_plan 的适用模块保存完整分析与资料覆盖，并分别保存方向与期限、当前投资吸引力、风险、把握程度，以及可检验的预测、复盘和经验。未提及的内容沿用；局部风险更新不会清空方向判断。观点、预测和专属框架的修订保留版本与原始日期，可带具体版本追问助手。用户指定的研究重点与研究员维护的重点分别保存，修订标明来源，AI 不能覆盖用户重点。每轮自动研究读取未决事件、研究问题、预测期限与已有经验，检查是否有值得复盘的新证据、反证或结果；复核状态留在该轮记录，证据不足或没有实质变化不制造复盘文章。正式复盘关联此前已发布的具体研究判断或事前预测版本，分别判断结果、机制支持和其他解释；主题标题或状态修订不代替事前判断，历史补建不能冒充事前预测。每个标的有自己的案例和适用边界，XLK 案例不自动成为其他资产历史。

同一预测、问题、日程、复盘和经验的局部修订，也保留未提供的假设、反证、状态与依据；明确提交空值才清除对应内容。独立核证只修正本次提出的变更，不用补齐模板的默认空值覆盖旧研究；不支持的修订可以放弃，原观点不会因此被撤回。AI 默认读取当前研究与旧版本索引，历史全文按版本取用，避免长期积累的重复正文挤占当前上下文。界面区分当前与历史判断，数值证据可展开查看当时计算值和口径；覆盖不足的静默检查仅表示已覆盖信息内未发现新增。

仅恢复已核证来源的系统引用修正，另存带原记录关联和修正原因的版本，保留原判断与历史；不计为新的市场检查或实质研究进展，也不推进当前判断的复核时间。

DeepSeek Harness 实际可用时，Watchlist API 在标的所在市场交易日当地 08:30 起（A股和港股为北京时间，美股为纽约时间、随夏令时切换）以最多四个并行任务，仅自动研究投资状态为“拟投”（Proposed）或“在投”（Invested）的有效登记标的，类型包括股票、ETF、指数、公募、私募和加密资产现货；关注、暂停、退出、未设置状态和已归档产品不自动启动研究。交易日使用 XSHG、XHKG 和 XNYS 交易所日历，跳过周末和休市日；未配置支持市场的指数不猜测更新时间。状态读取 Watchlist 实际保存的 coverage_status 最新记录，属于标的并在各列表间共享；状态变更在下一次自动范围读取时生效。每天先逐个处理当前可访问组合和现有列表：并行完成其中符合上述条件的成员研究，再执行该范围的风控研判，最后处理其余符合条件的标的。风控仍汇总完整列表和实际组合持仓的已留存事项，不删去其他状态的风险。手动和自动研究均每次处理一个标的，符合条件的美股行业 ETF 使用同一逐标的调度。原批量运行仅保留历史研究、来源及预期对照的读取，不再创建或恢复批量任务。从未研究或最久未更新者优先，重复成员按既有运行记录及标的市场当地日期去重，美股不会因北京时间跨日重复研究。失败保留原因而不反复自动重试，风控按实际可用的研究形成结论并保留缺口，不保证所有成员均已更新。服务较晚启动时继续处理，跨日仍优先未完成或最旧范围；页面显示每轮实际资料截止时间，不承诺所有标的已在同一时刻更新。其他状态的支持类型仍可手动发起单标检查，最新失败不会覆盖上一版完成的研究结论。同日完成后，实际检索范围出现新原文、修订或撤回、已有量化规则新触发、明确日程到期，可使用同一 worker 补充研究；同原文重收不重复触发。触发保留逐查询覆盖时钟，避免后来网页读取推进总截止时间而漏掉尚未检索的新资料；失败不反复消费同一批信息。

基金优先沿用已登记且支持的检查市场日历；没有支持日历时使用北京时间每日08:30的净值工作检查时钟，这不代表产品投资中国或应该每日披露净值。BTC现货使用UTC每天00:30的检查时钟、全年交易日历和已结束的UTC日线。没有新增净值、行情或材料时，研究可以保持不变，不伪造每日进展。

分析复用仓库外 `portfolio-copilot.env` 的 `DEEPSEEK_API_KEY`，结合留存标的资料、共享资讯库及必要的定向公开检索形成结论。网页更新时间、搜索估计日期和上传时间不代替首发时间；只有日期时保留日期，未知时不臆造具体时刻。搜索/读取失败放入覆盖缺口；文本包按渠道报告实际覆盖，不承诺完整新闻或社媒覆盖。

研究、事件、风险、独立事实核证及公开检索统一使用 `INVESTMENT_STUDIO_PORTFOLIO_COPILOT_MODEL_NAME`（默认 `deepseek-v4.1-flash`），原有推理设置与独立核证步骤保留。启动器先加载 [共享模型接口](../../infra/config/deepseek_harness.patch.yml)，再加载各任务的受限工具配置；使用 Harness 自带的 OpenAI 兼容接口，保留网关流式增量中的工具身份。`DEEPSEEK_BASE_URL` 同时传入 DSH、核证和研究工具，默认 `https://gateway.hzxxf.cn/v1`；该值是追加 `/chat/completions` 前的命名空间，标准兼容网关通常需包含 `/v1`。检索默认向同一 API 命名空间追加 `/messages`，可用 `DEEPSEEK_SEARCH_URL` 明确指定完整检索接口。接口只返回客户端 `tool_use` 或普通文本时，不作为已执行检索或无新增证据，记录真实覆盖失败；不自动切回其他服务发送凭据。

生成失败时不进入独立事实核证；运行记录保留明确的额度不足或模型通道不可用类别，不用后续“未提交草稿”覆盖首因，也不保存服务商原始错误正文或凭据。

运行环境的可用性检查与启动脚本使用相同的 `INVESTMENT_STUDIO_PORTFOLIO_COPILOT_ENV_FILE`，并读取当前发布目录内已安装的 DSH 与 PATH 中的 Node。部署时先以服务用户执行 `infra/harness/install.sh`，按冻结的依赖锁安装；每次研究直接运行 `infra/harness/run.sh`，不临时解析或下载软件包。生产环境须显式配置 Watchlist 自身的 `INVESTMENT_STUDIO_WATCHLIST_RESEARCH_API_BASE_URL`，以及 Portfolio、Regime 的 `INVESTMENT_STUDIO_WATCHLIST_RESEARCH_PORTFOLIO_API_URL`、`INVESTMENT_STUDIO_WATCHLIST_RESEARCH_REGIME_API_URL`。`data/research` 的方法、专属研究框架与历史案例，以及 [共同研究原则](backend/config/research_core.md)均为运行所需源文件。两个 DSH 入口加载同一份核心原则，任务提示只区分自动检查和交互。

投资研究使用一条统一进展时间线；主题内时间线引用其中与该主题有关的同一组记录，不另写一份进展。事件、研究问题、判断、预测、日程、复盘、经验及 PM 观点各保留自己的原始记录与版本。事件可以不属于主题，也可以同时影响多个主题；当前主题判断与逐次变化分开显示。

浏览器首读使用 `include_history=false`，历史底稿在打开档案后加载。浏览器先读取运行状态、当前判断及来源说明；展开已保存依据时，再通过该研究版本读取完整原文、快照或计算输入。状态接口不重复传输整份底稿和来源正文，档案列表也不预先下载每个历史来源的数据体。研究员及风控继续读取完整绑定证据，展示投影不会裁剪它们的输入或修改历史记录。

持续跟踪统一使用重点主题：一般约五个，最多十个活跃主题，按核心/重要及其决策意义排序。事件、研究问题、预测和日程是主题的证据或里程碑，不再另列独立跟踪队列。每个主题显示综合认识、最新实质变化、下一验证和可展开时间线；安静复核只更新检查日期。重要而无剩余研究问题的事项进入近期重要事项，操作审计放在折叠的运行记录。

重点主题可以从事件、数据或图表建立，也可以直接提出问题；新主题排队补充初始研究，界面明确显示待建立基线或运行不可用状态。提出来源、重要程度、固定状态与生命周期分别保存。普通用户主题可由研究员维护，只有明确固定的主题保留人工核心问题和生命周期控制。每轮研究回顾主题时间线、原判断、上一观察和相关投资观点，再决定更新、合并、替换或关闭。关闭与降低研究优先级分别说明，保留原记录，不以到期或没有新闻判为已解决。

事件的分析深度与后续跟进分别保存：重要的短暂变化可作简报，说明事实及可能影响后无需继续跟进；需要验证的事项列出下一步，明确完成后结束。短期价格反应不证明影响已全部计价，也不自动证明需要长期主题。持续关注不等于风险触发；机会可以跟进但不占风险提示，旧事项不会因缺少新消息自动解除。

投资观点可直接保存，也可明确授权研究助手记录。新观点必须带背景；从主题、事件、图表发起时预填并冻结精确来源和版本，单独新增则填写当时情境。期限、验证条件和改判条件按需补充。新的判断/复盘追加记录，文字更正保留修订历史；旧背景缺失明确显示，不事后补造。当前总体观点由用户明确选择某条观点的版本，最新随笔、复盘、经验不会覆盖它。AI复核归属研究员，不冒充或覆盖投资经理。

Watchlist 统一使用 Home 账号服务验证身份。显式配置本机模式后，本机浏览器免登录并使用真实拥有者的完整权限，可读取未认领的旧对话、附件和其他个人视图，也可维护旧研究；修改记录仍保留原作者，另记当前修改人。界面显示“本机全权限”。这一权限只来自 Home 验证的本机身份，云端账号和显式普通账号凭证不会因此提权。团队共用观察列表、研究档案、主题与正式观点，观点保存真实作者和每次修订；本人可更正原观点，其他成员可追加自己的复核。主题负责人可在现有团队成员中交接。只读成员可阅读并使用个人研究助手；被授权读取某个组合后也可发起该组合的风险分析，团队列表和标的的共享风险更新仍要求团队写权限；列表排序、列视图和显示偏好按账号保存。

研究助手对话默认仅本人可见，附件、历史回复和模型上下文同样私有。个人对话只有收到本轮明确保存指令，才可发布观点、主题或经过核证的团队研究。组合对话及其旧历史继续继承 Portfolio 当前访问权限，撤权后不能读取附件、历史、来源或运行上下文，也不能把组合内容自动写进团队研究。曾经变更过组合范围的旧对话保留全部原范围权限；继续讨论时需新建明确绑定组合的对话。

配置 `INVESTMENT_STUDIO_AUTH_URL` 指向内网 Home `/api/auth`；浏览器来源复用 Watchlist 的 `cors_origins`。后台研究使用具有 `watchlist:research` 的独立服务凭证，数值刷新服务的 `watchlist:maintenance` 只开放批量重算入口。模型仅取得短期单次 run 凭证，不接收登录主凭证；每次工具读取和最终保存均核对主体、范围及当前组合权限。跨服务再委托需服务器凭证的 `identity:delegate` 授权。

迁移 `20260908_0056` 增加团队、作者、个人对话与显示偏好归属。首版为单团队 `default`、多账号。旧未知作者保持未知；云端旧个人对话需管理员明确认领，本机全权限可直接访问；`claim_research_identity` 默认只预览，只有明确执行且指定目标成员时才映射旧临时身份。迁移与认领不自动执行在真实运行库。

研究助手的页面标的或组合必须与关联对话一致。研究档案、投资研究与风控专题由各自模块维护，通用对话接口不能修改其归属或内容。两个研究入口读取相同的绑定标的资料和档案，均可按需查询数值、原文及比较。正式发布比较本轮所研究的档案版本，旧快照不能覆盖已更新的观点；发生冲突保留草稿，助手同时保留回答并显示未发布。风控继续只读其绑定风险和持仓快照。

组合页面助手保留所选估值日、账户和持仓引用。工具先读取同日完整组合持仓，再分别附上所选账户、证券或 FCN／Option 合约明细，组合净值分母保持不变；风险页另读取该估值日的组合风险上下文。Portfolio 本地持仓引用不进入共享标的目录。历史持仓可以按当时估值日读取，但当前模型、配置与本轮形成的研究不冒充当时已保存的预测。

研究入队后若账号服务不能签发本轮凭证，任务立即标记失败并保留输入，可以恢复授权后重新发起，不永久占用队列。共享研究框架、用户研究重点和正式发布使用同一标的事务锁；观点修订在锁定当前版本后追加历史，范围内首个风控任务也串行入队。只读账号的界面保留查看、个人讨论和显示偏好，关闭共享名单、标的资料、风险规则和跟进的编辑入口。

投资研究和底稿读取通过 `20260920_0060` 的 PostgreSQL GIN 表达式索引，先筛选每次运行留存的 `instrument_ids`，再读取大体积证据快照中的必要字段。专题当前成员不替代历史运行范围；原文、来源、作者和组合权限继续从原记录核对。索引由数据库随写入维护，不增加研究缓存或第二份事实，升级前必须完成该迁移。具体合同见 [数据模型与 API](docs/DATA_MODEL_AND_API.md)。

历史组合权限读取通过 `20260923_0063` 的按专题部分索引，跳过 `portfolio_id` 与 `risk_scope.portfolio_id` 均明确为空的快照，避免公共研究专题的每次授权都重读全部原文。判断由原始 `context_json` 的不可变函数派生并随数据库写入维护；异常结构保守进入原有精确校验，不按标的、记录类型或完成状态删减历史边界。当前专题的组合归属仍与全部历史归属合并，原文中的 NUL 与字面转义不改写；该优化不增加权限缓存，发布前须先执行统一迁移。

原文中的 NUL 仅在数据库查询工作副本中处理；只有本次所选字段可能受影响时才回读原始 JSON，保留真实 NUL、原有替代字符和字面转义，不因无关原文而反复传输整份输入。

当前检查状态、当前底稿与风控结果使用服务端游标逐条读取，找到所需版本后释放游标；只取最新运行的查询在数据库中限制为一条。历史版本仍按原始日期、来源和权限完整回溯，不按数量截断历史。服务启动恢复中断任务时只更新状态字段，不把历史输入快照载入内存；后台入队也只检查本标的的活动运行。日内增量检查沿用历史检索范围时，同样先按留存标的范围筛选并逐条读取，遇到可用记录即释放游标，保留历史组合权限检查。

档案内的主题进度、研究动态和待复核事项复用同一次历史读取，历史组合归属批量检查；主题数量不会重复放大底稿扫描。风险汇总按本次完整范围批量读取价格风险、团队观点、市场日历和实际同类/基准数据，包括明确的缺失状态。读取结果仅在本次装配中共享，不跨请求缓存权限或研究配置。

普通研究 MCP 先通过 `read_research_context` 读取问题、范围、覆盖摘要和分区目录；标的目录、来源覆盖细项及对话历史按需分页，自动研究先读非空 `incremental_trigger`。`read_research_instrument` 概览保留当前判断，业绩、PM 档案、产品资料、已披露持仓与事件分别读取；已披露持仓读模型与来源机构的 holdings 表不是同一份数据。`read_research_dossier` 按分区读取研究任务、议程、问题、事实、预测、PM 观点与来源/版本索引，精确原文、历史版本和研究更新仍使用 `source_id / version_id / update_id`。每页实际返回不超过 48 KB；超长问题或当前判断在概览给出完整读取入口。选读内容沿 `next_offset` 和全部 `deferred.path` 继续读取，数组、字段和文本均可完整还原，不截断正文。PM 观点的依据从该 PM 原版本读取，不能换成后来同名来源；未读索引或分支不算已核实，也不代表没有新变化。

研究员通过 MCP `submit_research_review(result: ReviewResult)` 向 `POST /api/research/runs/{run_id}/sector-draft` 提交结构化增量。自动检查覆盖请求的全部标的；交互可更新已读取标的中的一部分。`change_kind` 区分 `none`、`knowledge`、`investment`；摘要、事件、主题和底稿可以为空，省略的内容与关联保留原值。接口校验标的和团队范围、来源、时间与原版本，仅保存 `context_json.submitted_draft`；校验错误反馈给研究员修正，成功返回 `pending_fact_review`，不发布结论或事件。提交成功仅代表草稿受理；应用在核证与发布完成后显示结果，聊天回答不重复 JSON。事件、主题和底稿的实质进展可以形成知识更新。`summary` 仅保留该轮 `investment` 输出的叙述，当前 AI 投资判断统一读取版本化的 `investment_view`；按维度修订后使用该版本的日期和来源，显式撤回不得恢复旧摘要。无变化检查保留原判断日期和来源，同时显示新的检查日期。

新研究中的底稿、研究员主题、候选提醒与自动复核摘要均交由独立核证；核证包按实际读取和明确引用选择完整证据，原文集中保存一份，概览与原判断通过来源索引关联。核证只依据本轮取得及沿用的原始证据，检查主体、数字、转载或自动汇编、方向、证据强度和研究问题的依据。即使没有事件，只要有底稿或主题变更也进行复核。核证使用绑定本轮草稿的逐项回执：每个标的、候选事件和主题均须明确接受、修正或剔除，接受不重复抄写正文；反思回执不能省略或改指其他原判断。底稿的结构化对象和记录只返回必要字段修正，未改字段从本轮原稿复制；不保留的拟议子变更须明确列入 `omit_fields`，不能以遗漏代替拒绝。被复核数组的每条原记录均须有回执：有稳定键的记录沿原键绑定，事实观察沿冻结原稿的零基序号绑定，输出顺序不改变原顺序。剔除一条事实会将其从本次事实集合移除；拒绝整个事实集合修订才保留旧集合。有键记录被拒绝仅取消该条本轮修订，既有记录保留。明确撤回仅限原稿已提出的撤回。回执展开后继续执行原有来源、时点、引用和发布校验，紧凑回执、草稿与展开结果保留在同一研究记录中；独立核证成功后才由既有 `apply` 流程在同一事务内保存主题、研究结论与事件，旧版本不能覆盖期间已更新的主题或事件。核证失败不发布未核证草稿。独立核证保留完整原始证据，单次调用在高推理设置下由思考与最终 JSON 共用 65,536 输出 token 预算；达到长度上限仍判为失败，保留用量、草稿与证据，不发布部分结果，也不放宽事实检查。核证以原生流式接口接收响应，将推理片段与结果分开，仅在完整结束标记、正常终态及全部结构和引用校验通过后发布；传输失败记录阶段、已收字节与片段数、耗时及可取得的用量，保留原有空闲超时与整轮时限，不自动重试。事实核证区分事实、解释与预测，不要求未来已经发生才允许形成有依据的前瞻判断。此流程不把旧历史摘要追溯标记为已经复核，也不保证新闻召回或模型判断完整。

投资研究中的进展记录默认浏览近七日真实进展，按研究记录形成或修订时间排序；这是展示范围，不是信息准入的时间上限。事件发生、原文发布、收录和研究更新的时间分别保存，日程另保留预计日期。今天基于旧证据修正判断属于今天的研究进展，不能标成今天发生的新事实；重要旧事实可补录，较早但仍有效的事项持续关注。相同当前判断与依据不重复追加，重新回到过去判断则保留为新的修订。没有重大新增时不制造提醒，也不因没有新消息自动解除原事项。量化统计和价格规则集中在“业绩与风险”。共同数值工具读取带版本和信息时钟的宏观/市场序列；价格风险证据提供半衰期 21 个交易观察、最低 63 个连续日收益、最多 252 个收益、252 年化的去均值加权对数收益 EWMA。低频净值和跨缺失交易日收益不套用此定义。当前值、历史参考和变化可支持风险研究；没有临时设定的自动报警阈值，也不把波动上升等同于未来下跌。

Watchlist、Portfolio 和标的详情的顶部右侧统一放语言选择；大标题右侧按“设置 / 风险提示 / 研究助手”排列，均作用于当前对象。风险提示汇总整个列表、实际组合持仓或当前标的中仍需关注的风险、重大不确定性及价格触发，同等优先级按最近进展排列，机会和已处理事项不占默认首屏。投资研究仍保留完整的研究结论、重要变化和风险机会。

风控研判复用上述盘前 worker，只为本轮有到时研究成员的列表和当前可访问组合排队；等待相关成员研究结束后，按各成员当地研究日及已绑定输入去重，依据已留存研究事项、价格触发与实际取得的持仓形成综合结论；单标的风控研判按需发起。它与标的研究分别留存输入和结论，失败保留上次完成结果。列表只是观察成员，不能冒充组合；组合使用 Portfolio 提供的实际市值、币种和净值口径，市值敞口及占净值比例不是风险贡献。没有聚合风险指标时明确缺口，不用权重推算。研究助手可读取这些结论、研究底稿及其原始依据，历史判断仍需按当时输入日期使用。风控先读取范围和实际持仓索引及完整概览页 offset 计划，再按计划条目的工具读取全部概览：普通页通过 `read_risk_instruments`，无法放入批量封装的大项明确指定 `read_risk_instrument` 单项读取，不阻断范围索引或跳过该标的；页之间独立，可并行请求，每页保留原标的概览的全部字段且不超过 48 KB。批量概览与单项页由服务端按本轮绑定输入直接投影，每页重新校验授权；完整页通过字节和序列化检查后，在同一运行的 `context_json` 内记录已交付页，不再每页传输整份上下文，也不增加缓存或独立持久层。重复页不重复写入，重新准备输入会清空回执。范围索引同时列出 `instrument_detail_reads` 必读明细页计划；通过 `read_risk_instrument` 完整读取非空风险事项和当前研究上下文，包括前次快照独有的记录；两端均为空的分区无需读取。同类比较按业绩研判需要读取。选读分区按返回游标读完，前后快照的移除项也保留，未读取的比较不能支持相对表现结论。比较默认保留共同样本起止、观察数和方法，完整共同日期可按来源单独分页读取，不重复注入每组比较。当前研究上下文明确区分用户选定的总体观点版本与 PM 档案历史原文（旧观点、逻辑、反证、期限与监测计划），团队可见的未完成 PM 观点原文、归属与版本日期，以及有效主题内持续跟踪的问题、反证、下一检查条件和预测到期状态；档案的负责人和维护人不冒充原观点作者。这些是待检验判断，不能作为独立事实，到期不表示兑现或证伪。工具逐页检查实际字节数，超大的单条记录明确报错，不把截断或未读取的证据视为没有风险。标的风险在 Watchlist 与 Portfolio 共用 case_id 和来源。

组合另从同一次 Portfolio 风险上下文读取实际持仓、生产风险贡献、各有效分类分别列出的 SAA/TAA 目标差，以及同模型重算历史持仓的 RC/相关性变化；多个分类不能合并成一个默认规划分类，各分类均按返回的权重或风险贡献口径解读。模型隐含相关性不冒充风险页自选窗口的样本相关矩阵，历史重算也不冒充当时已保存的 PIT 预测。没有配置偏离容忍带或变化阈值时，仅据实研判，不称为已越限。

FCN/Option 使用 Portfolio 本地未平仓合约与可信详情链接，不登记为 Watchlist 标的；底层已有 canonical instrument_id 的研究风险可同时进入组合。通过 `read_portfolio_risk` 按组合模块及逐合约读取绑定快照，保留币种、报价日期、实物/现金结算、生命周期、条件交付现金与股票、实际参考资源和条款缺口；没有概率或新增衍生品定价。合约来源绑定 holding_id，组合整体事项不必制造 instrument_id。研究助手读取的风险研判沿用相同证据。

风控使用 `submit_risk_review` 结构化提交，保存前先检查结构、绑定快照中的标的、合约与来源，再核对全部标的概览及必读明细页。缺页时拒绝保存，并返回精确工具参数供补读；空分区、重复读取、上一轮回执不能替代本轮必读页，分页须读完。页回执证明应用已交付证据，不证明模型理解或判断正确。错误可在本轮直接反馈修正；每次提交都必须包含完整的 `summary`、`priorities`、`limitations`，修正时不能只补交缺失字段，未通过校验的部分结果不保存。成功运行后发布综合结论。控制台回复不再充当JSON数据，避免长段中文、引号和Markdown使整轮结果无法解析。结构与范围检查不等于金融判断已被核证，模型解释仍需内容验收。

业绩研判不依赖是否配置价格报警线，结合已观察到的月度表现、回撤、持仓剩余成本损益与实际仓位；同类直接复用基金页已登记分类及地域，默认基准复用标的设置。比较使用同币种、频率、收益口径和实际共同观察日，不从组合成员推断同类，也不声称全市场排名。邮箱私募净值按来源交易日历及披露延迟判断：显式设置优先，未声明的邮箱私募采用一个交易日；正常未披露尾部不作为过期，实际序列内部缺点仍保留。

历史参考目前包括从 Market Intelligence 保留的 XLK 14 个精选案例，来自 183 个单日跌幅至少 3% 的合并候选事件段，价格覆盖截至 2026-08-28。它没有覆盖上涨至少 3% 的样本，也不是完整独立事件全集；本次复用未重新核证原文，缺少完整历史持仓权重与原文归档。案例只用于机制、背景差异和观察点类比，不能成为当期事实、事件概率或交易规则。方法与案例位于仓库 `data/research`，原出处和局限一并保留。

### 美股行业 ETF 数据增强

XLB、XLC、XLE、XLF、XLI、XLK、XLP、XLRE、XLU、XLV、XLY 的完整成份、公司资料、年度／季度预期与价格来自 `studio_market` 共享数值库。数据按全市场范围独立采集，查询按研究截止时点绑定不可变批次及来源；不再把明细复制进 ETF 参考资料 JSON。成份公司不因此进入观察列表。研究先检索共享文本库，再读取绑定版本原文；新在线补充也进入共享原文库，研究自身只保存引用。缺少数据或未进行检索时显示覆盖不足，不能据此认定无重大新增。

成份公司预期按每轮 FMP 采集快照留存，并按相同公司、预测财期、年度/季度、指标和币种比较。财期滚动及覆盖增减不视为上修或下修；原始预期未提供币种时依据同公司最近财报的 reportedCurrency 推断，保留财报日期、来源和推断状态；若仍未知则仅保留待核实读数，不能用报价币种替代。可比变化会进入每日分析和独立核证，只有重要变化才形成事件。预期对照界面目前支持上述 11 只美股行业 ETF；底层采集覆盖全美股，其他适用 ETF 明确显示尚未接入对照界面，已披露为商品资产的 ETF 不展示公司盈利预期入口。

每轮研究实际读取的标的资料、FMP 输入、原文证据和分析结果绑定在既有 ResearchEntry；重要事件使用 RiskCase 的 `sector:` 来源，由投资研究独立维护，不因价格风险重算被解除。每个事件的实质进展在既有 history_json 中保留完整当时快照，同一事实与来源不会因为日更重复追加。自动研究提交时，每个标的必须包含真实的复核回执（已复核或证据不足）；缺失即拒绝草稿并提示补齐，对话更新仍可省略。未检查、获取失败、无重大新增与持续事件分别保留。研究不执行交易。

## 本地开发

先按根目录 README 安装依赖，并在仓库外准备 `watchlist.env`。从仓库根目录启动后端：

```bash
PROJECT_ROOT="$PWD"
RUNTIME_ENV_ROOT="$HOME/.config/orataba/secrets/investment-studio"
source "$PROJECT_ROOT/infra/launchd/load_runtime_env.sh"
investment_studio_reject_repository_env_files "$PROJECT_ROOT"
investment_studio_load_env_file \
  "$(investment_studio_runtime_env_file watchlist "$RUNTIME_ENV_ROOT")" \
  INVESTMENT_STUDIO_WATCHLIST_
: "${INVESTMENT_STUDIO_WATCHLIST_DATABASE_URL:?watchlist.env must set the canonical database URL}"
PYTHONPATH="$PROJECT_ROOT/apps/watchlist/backend:$PROJECT_ROOT/shared-data/instruments/python" \
  "$PROJECT_ROOT/.venv/bin/python" -m uvicorn watchlist_app.main:app \
  --host 127.0.0.1 --port 8000 --reload
```

启动前端：

```bash
npm --prefix apps/watchlist/frontend run dev -- --host 127.0.0.1 --port 5173
```

前端默认把 `/api` 代理到 `http://127.0.0.1:8000`。真实数据库迁移必须使用根目录统一入口；不要单独升级 Watchlist Alembic chain。
