# Watchlist 与资产详情架构

## 1. 结论

Watchlist 不应继续以“基金详情页加若干条件判断”承载所有资产。当前主路径明确分成两类工作面：

- `public_fund / private_fund` 共用基金工作面，保留基金档案，字段、标签和页面文案按运营模型区分。
- `etf / equity / index` 共用上市资产工作面，行情与收益语义按资产区分。

六类资产均提供总览、投资观点、投资研究、业绩与风险。投资观点是 PM 自己的判断历史；投资研究是自动研究员整理好供 PM 阅读的结论、重要风险机会与进展；研究助手是各页面的上下文对话抽屉，不设独立详情 tab。自动研究覆盖所有有效登记的支持类型，11 只美股行业 ETF 保留 FMP 持仓与预期快照增强。

Watchlist、Portfolio 和标的详情共用标题工具“设置 / 风险提示 / 研究助手”，放在当前对象大标题的最右侧；语言选择独立固定在顶部右侧。设置作用于当前列表、组合或标的。列表风险覆盖整个列表，组合风险覆盖实际持仓，详情风险仅覆盖当前标的；从列表进入详情后，风险范围不再受来源列表限制。风险入口优先呈现仍需关注的风险，投资研究则呈现准备好供 PM 阅读的研究结论、重要变化和风险机会。

共同能力只包括 identity、数据覆盖、收益风险、taxonomy、投资状态、研究记录、监控与来源说明。基金条款、股票财务、ETF 持仓和指数方法论不互相复用，也不为缺失能力制造占位数据。

## 2. 模块边界

### Registry

共享 Registry 是 canonical instrument、identifier、币种、交易所、行情/NAV、quote policy、return semantics 和 source contract 的唯一所有者。Watchlist 不复制这些事实，也不写回行情。

### Platform

Platform 负责 provider 适配、目录发现、首次 materialize、行情刷新和 reference data。目录返回 `catalog_provider / catalog_symbol`，不把 FMP 的内部字段名泄漏成公共 API 契约。

### Watchlist

Watchlist 只拥有：

- 名单 membership、view、筛选与导出；
- type-specific taxonomy；
- 当前投资判断、人物分析、按资产类型定义的定性评估、人工 rating 与逐条研究记录；
- 自动研究结论、来源证据及重要事项的进展历史，与 PM 观点和助手对话分别保存；
- monitoring assessment；
- 基于 Registry canonical series 的收益、风险和同类比较 read model。

详情页通过 Platform 的 `/api/instruments/{instrument_id}/reference-data` 读取 provider reference sections。Reference data 是可重新获取的展示数据，不成为第二份 canonical 行情或 NAV。

## 3. 单一主源策略

每只 instrument 在建档时只选一个 primary market-data source。刷新任务不会因空响应或错误转向其他 provider，不双写同一序列，也不维护双源对账兼容层。

| 市场 / 资产 | Primary source | 当前能力 |
| --- | --- | --- |
| A 股股票 | FMP | 目录、profile、EOD、财务报表、key metrics、ratios、分红、拆股 |
| A 股公募 | DataHub Tushare | `fund_basic / fund_nav / fund_portfolio` |
| A 股 ETF | DataHub Tushare | `fund_basic / fund_daily / fund_adj / fund_portfolio`；provider contract 不从 FMP 写入 canonical 行情 |
| A 股指数 | 逐只决定；当前核心指数为 DataHub Tushare | `index_basic / index_daily / index_weight` |
| 港股 / 美股股票 | FMP | profile、EOD、财务、估值指标、分红、拆股 |
| 港股 / 美股 ETF 与共同基金 | FMP，前提是具体 symbol 有覆盖 | fund info、EOD、holdings、sector/country allocation、disclosures；共同基金的 EOD→NAV/total-return 语义未核验前不自动写入基金主链路 |
| 私募 / 对冲基金内部产品 | 邮箱或人工正式材料 | NAV、文件、条款与研究记录；不以 13F 或公开行情替代 |

FMP 13F 数据描述机构披露持仓，不是私募/对冲基金 NAV，也不代表完整组合、空头、衍生品或实时敞口，因此不能接入私募 NAV 主链路。

### A 股指数与 ETF 建档规则

当前核心 A 股指数固定使用 Tushare。新增指数时，只有精确 symbol 可解析且历史 EOD 确有数据，
才可在建档时配置为 FMP；验证失败就直接配置为 Tushare。该判断发生在建档阶段，不是运行时
fallback。
已配置 FMP 的 `^GSPC`、`^IXIC`、`^HSI` 等港股/美股指数可展示 provider 返回的 name、
exchange、currency 与 EOD，但通用成分权重接口不可假定存在。

A 股 ETF 固定使用 Tushare；港股、美股 ETF 固定使用 FMP。新建市场或修改 provider 合同时，
必须用当前账户重新核验 entitlement、精确 symbol、历史 EOD、币种和字段语义，并把结果落实为
建档配置；不能把旧抽样结果变成运行时 fallback。

### 跨市场分类与同类比较

- `instrument_type` 回答载体类型，taxonomy 回答投资类别或策略；上市地、注册地和主要地域敞口不再混进同一棵分类树。
- 公募、私募、ETF 和指数按跨市场投资类别分类；股票按市场与行业分类。所有赋值只能落在叶子节点，父节点只用于导航和聚合。
- 公募、私募、ETF 和指数使用单独的 `primary_geographic_exposure` 表达主要地域敞口。它不是上市交易所，也不是基金注册地。
- 同类比较只使用完全相同的 taxonomy 叶子；基金、ETF 和指数还必须具有相同主要地域敞口，股票则由 taxonomy 市场根节点确定地域。不会向父类回退，也不会将 `其他`、`待分类` 当作有效同类组。
- `candidate_count` 是地域过滤后、日期过滤前的独立同类数量；`sample_count` 是与目标同一计算日且可比较的独立同类数量。少于四个独立同类时保留统计描述，但不生成百分位。

## 4. 详情页信息架构

| 资产类型 | Tabs | 核心内容 |
| --- | --- | --- |
| 公募 | 总览 / 投资研究 / 投资观点 / 业绩与风险 / 基金档案 | 净值摘要、PM 观点、经理与风格的研究结论、重要变化、披露持仓和材料 |
| 私募 | 总览 / 投资研究 / 投资观点 / 业绩与风险 / 基金档案 | 净值摘要、PM 观点、策略与管理人材料的研究结论、风险机会、锁定及申赎条款 |
| ETF | 总览 / 投资研究 / 投资观点 / 业绩与风险 | 单张主图、PM 观点、按底层资产分析的当前结论、风险机会及进展、收益风险 |
| 股票 / 指数 | 总览 / 投资研究 / 投资观点 / 业绩与风险 | 单张主图、PM 观点、公司或指数的研究结论、重要变化、收益与回撤及价格规则 |

Listed 页面不再设置“资料与明细”或固定研究问卷。价格与累计收益在总览切换，业绩页只绘制历史回撤，避免重复主图；FMP 持仓与预期仍作为 AI 研究上下文，在相关事件证据中按需引用。

Morningstar 可作为信息密度、同类比较和研究工作流的参考，但页面不复制其 rating 语义，也不展示当前数据源无法支持的模块。

## 5. 投资研究工作面

“投资观点”使用 PM 自己的判断时间线：每次新判断增加一条，日期、正文与当时背景必填，标题和来源可选。主题、事件及图表入口自动带入背景与原始版本，用户可以补充。当前总体观点由用户明确选定具体记录及版本，不由最新笔记或旧档案推定。更正已有笔记保留既有修订机制；原 profile 文本可只读展开。自动研究结论和研究助手回答独立保存，不自动写成人工判断。

公募与私募也使用追加式投资观点，原固定问卷不再作为页面研究主入口；已保存的历史 profile 仍可只读查看。基金档案按持仓、团队、策略、条款和材料折叠展开，保留原材料上传和编辑能力。基金总览仅保留摘要，净值、基准和回撤图及区间指标统一到业绩与风险。

“投资研究”面向 PM 阅读已整理的研究成果，默认展示最近完成的当前结论、重要风险机会及进展；证据和覆盖缺口展开查看。首屏说明当前判断、吸引力、风险和重要变化；持续事项统一纳入按重要性排序的重点主题，通常约五个、最多十个；主题摘要显示当前认识、最近变化和下一观察，展开显示分析、图表与时间线。无需持续研究的重要事项单独列出；深度研究报告按适用模块提供全文。方法、原文、历史和检查记录默认折叠。没有重大新增不制造提醒。最近一次检查失败时保留上一版完成的结论，同时显示本次失败状态和实际研究时间。

专属研究档案复用 `ResearchTopic / ResearchEntry`，无需另一套持久化表。`GET /api/research/instruments/{instrument_id}/dossier` 只读返回适用方法、材料、历史案例和最近完成底稿；`include_history=true` 可读各轮重要变化。`POST .../dossier/materials` 保存文字材料，`POST .../dossier/files` 复用原文件上传和提取能力，使用稳定话题 `dossier:{instrument_id}` 和 `kind=evidence`。档案还可读取明确只属于该标的、未关联组合的对话上传材料，以及基金档案实际本地原件；不把聊天观点或其他范围的私有材料混入。

材料保留真实正文、出处、发布日期、资料适用日期和收录时间。PDF 仅提取文字层，空页页码不算正文；文件缺失、只有目录或无法提取时明确说明。资料日期与源采集时间不互相替代，研究运行截止也不充当实际抓取时间。底稿引用原文、真实数据快照及材料的来源标识，框架和以前的 AI 总结不能成为独立事实证据。

持续底稿保存在已完成研究的 `context_json.reviews[instrument_id].research`，包括按适用模块组织的完整分析、关键驱动、稳定 key 的研究问题、支持与反对证据、下一步核实及重要变化。旧问题未提及不删除，也不自动否定；有明确新依据时可以修订为支持或反证。各轮保留原始来源及时间，失败不覆盖上次完成版本。底稿随实际研究生成，方法和档案入口覆盖全部支持类型并不意味着所有标的已经完成深度研究。自动研究不覆写 PM 观点或自行改写 skill。

“研究助手”从所有页面打开对话抽屉，结合当前页面、所选标的和展示条件回答问题，复用 `ResearchTopic / ResearchEntry` 对话和文件存储。用户提问才发起对话分析；仅打开页面或上传材料不触发这次对话的模型调用。对话历史与自动研究话题隔离，普通回答不作为自动事件。它不取代 PM 投资观点，也不要求 PM 先聊天才能看到投资研究成果。

助手可读取当前标的的研究档案、持续底稿及原始依据，并读取当前列表、组合或标的的已保存风控研判。先读取档案摘要，再按来源标识取长材料或历史案例；保留来源范围和当时日期，不把旧结论当作本轮新证据。

自动研究读取实际留存的 reference snapshot、收益风险、持仓披露、经理/策略/条款和研究材料，按资产类型解释。公开检索与原文获取在既有带凭据的 MCP 进程执行，搜索结果、原文和获取缺口随本轮研究保存。搜索仅使用公开名称和主题，不把私有材料或持仓发送给公开搜索。材料目录没有正文时不得当成已阅读；旧对话和人工观点也不独立证明新事实。

研究员通过 MCP `submit_research_review(result: ReviewResult)` 调用 `POST /api/research/runs/{run_id}/sector-draft`，一次提交本轮完整结构化结果。接口校验完整标的范围、来源、时间和底稿，校验错误返回工具供研究员修正后重新提交；成功仅保存 `ResearchEntry.context_json.submitted_draft` 并返回 `pending_fact_review`，尚不发布研究结论或事件。助手最终只确认提交，不在正文再次序列化 JSON。

程序检查候选来源资格，再对已提交的新研究底稿及候选事件做一次仅根据已取得或保留原始证据的独立事实核证，核对主体、数字、首发与转载、方向、证据强度以及底稿问题的依据。没有事件但有底稿时仍须核证，核证须返回完整修订底稿；可修订或删除候选，只有独立核证成功后才进入既有 `apply` 流程保存研究结论与事件，失败不发布未核证草稿。旧历史摘要不会因此追溯获得核证标记。新闻召回与模型判断仍可能不完整，缺口单列。

仓库 `data/research/frameworks.json` 保存可组合的公共领域方法，按实际底层、管理方式和产品条款生成研究计划；专属问题与用户约束保存在各标的 mandate。`data/research/historical_cases/xlk.json` 保留旧 Market Intelligence 的十四个 XLK 案例及原出处。它从一百八十三个日跌幅至少 3% 的合并候选段中精选，价格覆盖截至 2026-08-28，尚未涵盖上涨至少 3% 的案例。本次复用没有重新核证原文，也缺少完整历史成份、权重快照和原文归档。只能比较机制、事前状态、差异和观察点，不用案例数量推算概率、收益或交易规则，也不以历史案例单独证明新事件。

风控研判复用现有盘前 worker：只为本轮有到时研究成员的当前可访问组合和现有观察列表排队，以最多四个任务并行完成其中符合条件的成员研究，再执行该范围的风控研判；单标的风控按需发起。范围按各成员市场当地研究日及留存输入去重，美股不因北京时间跨日重复研判。它读取已留存的重要研究事项、价格触发及 Portfolio 实际持仓，与研究员的底稿分别保存输入、结论和运行状态；失败不覆盖上次完成研判。列表成员不表示持仓。组合中的实际市值及市值占净值描述敞口，不能写成风险贡献；缺少聚合风险指标时保留缺口，不以权重自行合成。成员研究失败时保留缺口，日更研判使用运行时实际取得的研究和持仓，各输入日期与研判时间分别显示，不保证所有成员底稿当日已经更新。

PM 的当前判断与人工研究记录不保存在 `instrument_manual_profile` 的整包 JSON 中。它们分别使用
`instrument_research_profile` 和 `instrument_research_note`：更新当前判断不会覆盖历史记录，单条记录
有独立新增、修改和删除接口。profile 与 note 每次实际变化都写入不可变 revision；相同内容的重复
保存不制造新版本，删除 note 只做可审计软删除。

公募分析关注基金经理、投资风格、基准、费用和带报告期的披露持仓，不能当作实时组合；私募分析关注实际净值频率、策略证据、流动性及管理人材料，未披露的敞口、杠杆和对冲不能从净值反推。股票分析关注经营、盈利和预期，指数分析关注编制与结构。ETF 先区分行业股权、宽基、债券、商品及跨境敞口，再取实际来源与适用指标；不把美股行业股票 ETF 的公司 EPS 能力套到所有 ETF，也不以相似产品填补缺失持仓。

投资研究中的进展记录默认展示近七日；这只是展示范围，不是信息时间准入限制。发生时间、首发时间、首次收录时间独立记录，仅有日期或未知时保留原精度。旧重要事实可补录，不能写成当日发生；较早但仍有影响的事项持续关注。事件使用稳定 key，实质变化追加完整快照，相同事实不因每日检查而重复创建。没有新消息不自动解除，只有有证据的解除进展才改变状态。名单“重点关注”是事件与价格触发的简短入口。

自动日更在 Harness 实际可用时由既有后台 worker 执行，仅覆盖共享登记库未归档、Watchlist 有效且投资状态为拟投或在投的六类支持标的，不限于名单成员。A股和港股在北京时间 08:30、美股在纽约时间 08:30 起运行，IANA 时区自动处理夏令时；交易所日历排除周末和休市日。私募保留境内交易日早间研究；未配置支持市场的指数不猜测时区。`sector_research.run_daily_reviews` 先逐个处理上述组合和列表，以最多四个任务并行完成符合条件的成员研究及后续风控，再继续其余符合条件的标的。包括 11 只行业 ETF 在内均按单标的执行，从未研究或最久未更新者优先；重复成员按已有运行记录和标的市场当地日期去重，失败留存而不无限重试。交易日较晚启动时仍可继续处理，实际覆盖以每只标的的研究时间为准。手动单标的检查复用同一链路，名单级手动入口仍保留原 11 只行业 ETF 范围。

### 5.1 基金判断与评分

基金分类、量化指标和人工评级语义保持分离，不计算自动综合评分；详情页以观点时间线为研究入口：

1. `Instrument Taxonomy`：回答“它是什么”，用于定义可比 universe。
2. 定量 read model：收益、回撤、波动、Sharpe、peer rank，只描述可验证结果。
3. `Qualitative Assessment`：edge、流程、团队、组合构建、风险、容量、条款、治理和组合角色等基金专属受控结论；可用于详情、列和筛选，不作为多资产 Group By 维度。
4. `Manual Rating`：1–5 星的当前 conviction，由研究员给出，并在 `Research Record` 留下证据与变更原因。

收益率、Sharpe、规模和定性标签不能直接相加成一个自动投资评级。若未来需要 model score，必须先定义同类 universe、字段方向、缺失值含义、权重版本、as-of 和适用范围，并与人工 conviction 分开展示。

## 6. 当前实现决策

- 证券目录公共契约使用 provider-neutral 的 `catalog_provider / catalog_symbol`。
- A 股股票固定使用 FMP；A 股公募和 A 股 ETF 固定使用 Tushare，港股/美股 ETF 固定使用 FMP。
- 系统没有 CSI 官网 fallback、运行时 provider fallback 或双源主序列。
- FMP 与 Tushare 的资料按实际覆盖保留在数据层；listed 页面只在决策相关证据中引用。
- 各类详情页均提供投资观点和投资研究，研究助手为跨页面对话抽屉；基金另设折叠档案。
- 私募 Organization 记录管理人、GP/受托人、行政管理人、托管人、审计师和 prime broker；公募记录管理公司、基金经理和任期。
- Fund Detail 没有第二套 People、Strategy、Documents 状态；基金风险指标、同类排名与人工 conviction 分开展示，不计算未经校准的自动风险积分。
- 投资观点使用逐条 note、不可变 revision 和总体观点选择记录；旧 profile 判断只读保留。
- 六类资产共用简洁观点时间线，取消固定研究模板；助手回答保存在对话中，自动研究与进展使用既有 ResearchEntry 和 RiskCase，互不自动转换。
- 基金/ETF/指数 taxonomy 使用跨市场投资分类，股票使用市场与行业分类。
- Peer policy 固定为同一叶子、同一地域和同一计算日，不向父级回退，也不用其他期限替代 1Y 主排名。
- Watchlist 的当前观点投影自用户明确选定的观点版本，研究阶段等管理字段沿用 profile，笔记计数等沿用 note；Group By 只使用对当前名单全部资产成立的聚合维度。Monitoring 同时暴露缺失判断、到期复核和到期跟进。

### 6.1 成份预期历史

11 只美股行业 ETF 的完整持仓、公司资料、年度/季度预期和最近价格由本项目既有资料维护任务直接采集 FMP，存入共享 PostgreSQL 标的资料的 `sections.sector_market_data`；不依赖仓库外数据库或旧路径。每次采集独立追加 `InstrumentReferenceObservation`，同时更新当前 `InstrumentReferenceSnapshot`，是否运行或成功完成模型研究不影响历史留存。持仓保留现金、基金和期货等非股票项目，既不截断完整持仓，也不把股票权重重新归一化。普通资料页省略这份重型研究输入；研究按截止时点读取已经采集的观察并绑定到既有 `ResearchEntry`。缺少本项目观察时明确记录缺口，不回退外部库或伪造预期基线。`GET /api/sector-research/estimates?instrument_id=xlk` 和研究工具使用同一采集历史，比较截止时点之前的最近两次观察。历史从实际采集时点开始，目标财期、持仓披露日期、供应商更新时间和本项目观察时间分别保存。

比较严格对应公司、年度/季度频率、目标财期、指标及币种。预测财期滚动、覆盖新增或消失、未更新的源采集记录均不称为预期调整。FMP 原始预期未提供币种时，可依据同公司最近财报的 reportedCurrency 推断，并保留财报日期、来源摘要和推断状态；若财报币种仍缺失则保留待核实读数，不能用股票报价币种替代，也不能合成 ETF EPS。共识样本数变化一并披露，非正基数不显示误导性的百分比。正式可比较的调整才可作为结构化事件证据交给分析师及独立核证判断重要性；快照时间不是精确调整发布时间。其他 ETF 的预期覆盖明确显示未接入。

## 7. 数据能力边界

以下内容暂不伪造，也不通过另一 provider 兜底：

- FMP 未覆盖指数的行情、任意指数的官方方法论 PDF 与调仓规则；
- FMP 未覆盖基金的持仓、费用或 AUM；
- 13F 未披露的对冲基金 NAV、空头、衍生品和完整风险敞口；
- 缺少分红再投资证据时的基金 total-return NAV；
- 缺少同日共同观测时的 benchmark 相对指标。

这些是来源能力边界，不应以空对象、推断值、静默 fallback 或第二套数据管线掩盖。
