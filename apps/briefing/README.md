# 市场简报

第四个独立应用：日报与周报使用 Studio 的公共数值数据和接收的文本版本，由受限的 DeepSeek Harness 解释证据。没有 Codex CLI、外部研究数据库或自动补写报告路径。

阅读页先列出本期已保存的重点标题，按报告原有顺序链接到正文；前四条直接显示，其余按需展开，不额外生成摘要或改变原文排序。阅读页沿用原日报周报的编号条目、主题标签、相关行情与原始链接。日报每条通常约 100–160 字，周报以短句交代本周变化和讨论问题；校稿同时压缩重复内容，必要的时间、观点归属与条件优先保留。每条正文或发布数据以来源数量展开文章标题、发布者和日期，原始链接直接打开发布网站；留存原文放在“来源与覆盖范围”内按需展开。报告章节可通过文内目录定位，来源跳转只展开同一期报告，不重新加载或清空正文。价格证据抽屉保留资产、期初和期末价格，可在两端来源与摘要之间切换。个股行情只展示正文实际关联的证券，并保留真实收盘日期和价格口径。

日报与周报仅在有重要且已确认的本期发布时列出“重要宏观发布”。“宏观数据”使用数值对照表，货币／财政政策和央行沟通使用事件条目；发布日期单列，数据所属期和单位仅按留存字段原文展示，旧报告没有独立留存的单位／期间不得从名称或描述猜测补齐；实际值、政策决定、发布前预期和前值均须有原文依据，缺失字段显示“—”并明确为来源未提供，区别于 0 和不适用，未来日程与补录的历史发布不进入该表。行情与宏观存量指标只展示成稿实际关联或引用的数值，完整候选输入继续保留供核证。存量报告仍按原有正文读取，不补写缺失的历史宏观发布表。

报告列表按日报／周报类型和分页范围读取，以日期分组；可按月份、报告日期或界面双语固定报告标题（投研日报／投研周报、Daily research briefing／Weekly research briefing）定位，筛选只查询摘要标量，沿用团队／任务身份与公开正式版的原权限，不搜索或加载正文。筛选不替换当前正在阅读的版本；主入口选择该日期最新的已完成版本，早期版本与失败尝试保留在版本历史。失败页提供已加载范围内的同日或邻近可读版本入口。选择新一期只读取正文并将焦点移到文章标题，同类型的浏览器前进／后退不重复下载列表；同一报告的章节跳转保留正文和阅读位置。

“行业研究”是单独的阅读入口（`?type=industry`），首项为美股科技，以 XLK 实际成份为核心，产业链其他公司作为背景。入口通过共享工作区 URL 规则（可配置 `VITE_WATCHLIST_URL`）进入 Watchlist `/instruments/xlk?tab=investment-research&mode=report`，保留界面语言。正文与交互研究共用同一档案，由 Watchlist 的账号与团队权限保护；Briefing 不获取或复制团队研究、PM 观点和私有持仓，不另存报告或触发行业报告生成。行业页不读取或轮询日报周报接口，公开入口本身只展示研究范围。

后端 `briefing_app.main:app`，本地 API 8010，前端 5175；云端 API 8110，网页 3103。数据库独立 `briefing` schema，通过统一迁移入口维护。后端配置使用外置 `briefing.env` 与 `market.env`，DeepSeek 沿用外置 `portfolio-copilot.env`。凭据不写入仓库、报告或 MCP。

模型接口复用 [共享 DeepSeek 配置](../../infra/config/deepseek_harness.patch.yml)，通过 Harness 自带的 OpenAI 兼容接口读取 `DEEPSEEK_BASE_URL`。该地址是 API 命名空间，默认 `https://gateway.hzxxf.cn/v1`；写作与独立校稿统一使用 `INVESTMENT_STUDIO_PORTFOLIO_COPILOT_MODEL_NAME`（默认 `deepseek-v4.1-flash`），均保留高推理设置。

日报窗口是截止时刻前 24 小时；周报重新检索本地周一至截止时刻整周的文本版本。发布时间、源站观察时间、本机接收时间分别检索去重，源站观察不代表事件发生。仅在本期接收到的历史资料单独计数，作为可搜索的补录背景；上下文直接提供按频道分组的完整本期标题索引，模型选择相关正文核实，并按需查找历史资料。提供完整索引不代表所有正文均已阅读。全文、来源节选和正文缺失分别展示数量，不能把节选当成完整文章。报告仅保存文本版本引用和元数据，正文从共享文本库按绑定版本读取。数值小表保存为本次快照，逐资产展示实际收盘日期；数字由程序计算，正文数值引用必须与原始资料或数据字段一致。

本地默认 `INVESTMENT_STUDIO_BRIEFING_EDITION_ROLE=preview`，可手动生成预览。云端正式发布设为 `publisher`，通过 `infra/systemd/install_briefing_timers.sh` 配置日报 08:30、周六 09:00（Asia/Shanghai）；`BRIEFING_DAILY_ON_CALENDAR` 和 `BRIEFING_WEEKLY_ON_CALENDAR` 可由部署按数据包到达时间调整。计划任务会等待报告成功或失败，触发时间不代表数据齐备，覆盖缺口始终随版本保存和展示。 页面通过只读定时器状态显示下一次生成或明确的未启用/已停止状态，并独立显示最近可读版本和最新尝试；不能用缺期猜测生成失败。发布端只读取既有 Linux 用户定时器，不自动启停；无法读取时显示未知，本地预览显示不自动发布。列表筛选不改变该状态摘要，版本信息仍遵循原报告的团队与发布权限。

计划报告先等待公共文本同步成功，再确定报告截止时间；重启后积压的数据包不会与报告创建并行抢跑。同步失败会阻止本次计划报告启动，保留失败状态；已完成的同步也不代表供应商原文完整，报告仍如实保存覆盖情况。

计划任务提交报告后，只读状态查询遇到连接中断、超时或 HTTP 502/503/504 会在原有 65 分钟总期限内继续观察同一报告，不重复提交。认证和权限错误立即停止，报告自身失败也不会被查询重试掩盖。

阅读入口同时显示报告日期、资料窗口与时区、生成完成时间、行情有效日及来源缺口计数；完整渠道名称按需展开。日期统一为 YYYY-MM-DD，时刻按报告时区显示至分钟，原始精确时间保留在时间元素的详情中；“已完成”只表示生成流程结束，不代表来源齐备。原始报告内容不随界面语言改写；固定控件和错误状态随语言切换。来源详情继续保留逐渠道失败原因和留存证据。

来源目录按标题、发布者或链接搜索本期全部留存材料，可按正文完整性筛选，每页 30 条；搜索和筛选不受当前页限制，也不修改报告引用及来源版本。目录先显示数量和正文覆盖，数值与逐渠道采集记录按需展开；阅读页顶部的缺口提醒继续保留。

手动生成默认使用提交时的当前时间；自定义截止使用日期时间控件与明确时区（Asia/Shanghai 或 UTC），提交前显示有效时刻及将创建新版本，取消不会请求生成。历史版本、失败记录与之前成功报告均可查看。服务商返回 `model_not_found` 或无可用模型通道时，页面保留明确的配置错误；不会自动换模型或发布未校稿内容。模型只能使用当前报告的来源索引、绑定版本正文阅读和结构化草稿提交工具。首轮完成草稿后，在同模型的独立校稿会话中逐条重读所引原文，校正事实归属、条件、时间和金融含义；两轮正常退出、校稿已提交且通过引用校验才形成已完成版本。校稿不更换资料窗口或新增选题。

报告版本号与同日重复生成的合并均限定在所属团队；不同团队可独立拥有同类型、同日期的第一个版本。公开页面只投影已完成的正式版本，保留原文与生成操作仍按团队身份授权。

写作和校稿各自的 MCP 进程记录本阶段实际返回的来源正文页，提交前必须取得每个引用来源的全部留存页；只看索引、首段或跳过中间页都会明确拒绝。两阶段不共享读取记录，进程重启须重新读取。该检查仅证明资料已返回给模型，不证明模型理解正确；`source_excerpt` 和 `unavailable` 仍保留原覆盖限制，不会变成完整原文。

验证：在根 Python 环境运行 `pytest apps/briefing/backend/tests`；前端目录运行 `npm test` 与 `npm run build`。测试使用临时 SQLite 和模拟 Harness，不发起真实模型调用。显式配置 `INVESTMENT_STUDIO_TEST_POSTGRES_URL` 后，迁移回归还会创建并清理独立 PostgreSQL 测试库。

行情变化按数据截止时点前已收盘的真实交易日选择。单日报告要求相邻两个应有收盘价；周报要求上周末锚点与本周已收盘区间完整。缺失交易日或尚未确认的交易日历均保留明确覆盖提醒，不用较老的两条价格冒充单日变化。数值缺口在阅读页顶部及来源详情同时显示。
新报告保存 `closed_sessions/v1` 行情期间方法版本。旧报告原始结果不重写，阅读时显示其交易日期间尚未核验的历史合同提示。

列表和状态轮询只查询摘要标量及 `source_count/edition_role`，不加载完整 input/draft/result JSON。详情仍保留完整报告与按需原件读取。行情主表、价格摘要、期初和期末原件均展示价格单位：固定基准使用已声明的标的单位，相关证券使用本报告绑定的 listing profile 币种，不使用财报币种或今日资料改写历史。无法据留存资料确认时明确显示单位未留存；指数点与货币价格分开。宏观发布按发布日期顺序显示，不把政策决议伪装成数值指标。
