# Portfolio Copilot：真实截图 Shadow 验收记录

## 边界

- 原始样本只保留在本机 `/Users/shaw/Desktop/截图`，不复制、不改名、不提交到仓库。
- 该目录包含不同 Portfolio 的样本，不能一次性作为一个批次上传。
- 每个用例开始前，由用户人工打开目标 Portfolio；该 Portfolio 是不可由 Agent 修改的任务边界。
- Agent 只能在当前 Portfolio 的账户、衍生品合约、标的和既有交易事实中解析引用；不能新建账户，也不能跨 Portfolio 路由。
- 全部测试停在不可变分析修订和 Preview，不执行 Commit。
- 文件名只是本地用例标识；金标准文档不抄录账户号码、持有人、成交金额等敏感正文。

## 账户分配金标准

每个候选必须返回下列四种状态之一：

- `resolved`：当前 Portfolio 中只有一个账户同时满足产品类别、币种、机构/账户提示和有效日期；输出的 `account_id` 必须与 Preview 行一致。
- `ambiguous`：存在两个或以上合理账户；列出当前 Portfolio 内的候选账户并提出人工选择问题，不生成交易提案。
- `unavailable`：当前 Portfolio 没有符合产品类别和币种的账户；不临时创建账户、不借用其他 Portfolio 账户。
- `not_applicable`：候选本身不需要账户，例如未知文档或纯账户元数据。

截图中的 Portfolio 名称、产品名称或持有人信息只能作为证据，不能覆盖用户当前打开的 Portfolio。截图中的券商账户号或姓名只是账户匹配提示，不是系统 `account_id`。

## 记录结果

每个用例分别记录 DeepSeek 路线与 OpenAI 视觉基线的：

1. 每张图的文档分类；
2. 候选数量及跨图合并/拆分是否正确；
3. 账户状态和 resolved 时的准确 `account_id`；
4. 逐字段的 observed / inferred / ambiguous / missing 判断及证据引用；
5. 既有交易匹配与重复判断；
6. 快照是否被错误转换成交易；
7. Preview 的有效行、错误行和规范化结果；
8. Agent 提出的问题是否足以让人完成复核。

页面复核还需记录：既有合约选择、新合约条款修订、现金/转账/换汇的双账户字段、
多记录批次重排、重复候选排除，以及页面刷新后的账本登记状态。模型输出仍只提供候选；
这些字段最终以 Portfolio Preview 的业务校验结果为准。

先完成人工金标准再设定通过标准；不以模型自报置信度代替字段、账户和账本规则验收。
