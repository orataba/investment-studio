# 投资研究系统

本文是数据、量化、研究员、PM 与风控共同遵守的研究合同。服务及权限边界见 [Architecture](ARCHITECTURE.md)，工具及页面入口见 [Watchlist README](../apps/watchlist/README.md)，原始数据和信息时钟见 [Market Data Pipeline](MARKET_DATA_PIPELINE.md)。

## 运行控制和在投更新范围

业务关注状态、账号权限和模型运行控制分别持有。`studio_runtime.model_work` 动态读取服务用户的 `~/.config/investment-studio/model-work.json`；缺失、损坏或 `paused=true` 均阻止模型启动。Watchlist 请求、派发、领取、恢复、真正启动，以及 Briefing 和截图分析共用开关；等待模型时也观察暂停并终止进程组。资料保存、公共数据接收、NAV 与确定性组合计算继续可用。

所有当前 `Invested` 且登记有效、详情 active 的标的均可更新，不设试点名单或每类数量限制。以最新业务状态为准，不把持仓名称、待办主题、重试或过期租约当作在投资格。`RESEARCH_AUTOMATIC_ENABLED` 默认 false，仅云端启用自动研究，本地保持暂停。共享研究更新执行在投资格校验；人工私有讨论仍遵守全局开关和原权限。自动风控按在投标的的必要事项排队，不重复遍历列表、QA 范围和组合。

暂停保留输入和草稿，以 `paused` 表示尚未完成的研究，不能当作成功或研究失败；恢复主机开关不会重放已暂停积压任务。简报在最终发布事务也检查暂停，保留原始资料与草稿而不生成已完成版本；截图分析按原执行尝试保存暂停终态和原件，迟到回调不得覆写。运行控制不改变投资状态、实际持仓或凭据。配置见[模型运行控制](SERVER_DEPLOYMENT.md#model-work-control)。

## 增量监测与冻结工作集

登记类型、已披露底层策略、产品机制分别表达。`research_applicability` 只使用已有登记资料，不从名称或平滑 NAV 推断策略、杠杆、持仓及披露频率。私募先看持续主题、策略和材料，取消通用每日新闻检索；管理人、条款、申赎及运营重大事实和已引用来源的更正撤回仍受监测。配置交易市场时沿该日历；仅无适用交易市场而回退 `fund_nav` 的检查时钟才覆盖周末，这不意味着每天启动模型。

0070 的 `research_monitor_state` 分开保存廉价扫描水位、待处理变化、已经尝试的版本与成功应用水位。跨日没有新增资料、真实约定到期或领域风险变化，不创建新模型任务；普通价格、NAV 或持仓刷新本身也不触发全量研究。失败或暂停不消费待处理变化，同一批变化不会每轮排成新任务；新资料会合并未完成部分。只有发布成功，才原子确认本次冻结窗口中的确切变化，新扫描到的变化继续保留。到期去重仅保留仍有效的当前版本，旧期限不自动补造。

正式单标的任务的 `research_working_sets` 固定基线版本、持续跟踪事项、重要且 active 的主题、来源依赖和本轮受影响集合。候选主题只携带必要当前态；来源关联明确的更正撤回和约定到期决定必须复核集合。关联未知的新来源可支持经核证的稀疏更新；未提交的主题不记为本轮已复核，原判断日期不变。模块长正文、结束事项、旧判断及原件沿现有分页工具按确切版本读取，不把历史数量变成任务范围。未解除的实际风险仍可见，研究跟踪结束不解除风险。

冻结数据不等于已经发送给模型或读完原件；工具目录也不是证据交付。按原版本读取仍检查标的、团队、组合、运行尝试和截止时点，旧原件保持各自来源及日期，未知时点不补造。发布在既有锁和基线 CAS 下把稀疏提案合并入完整当前底稿，保留未选中内容、未知历史字段和原始依据，不把精简输入写回覆盖历史。

0071 以精确事件版本的已保留终态风控决定回填 `last_assessed_snapshot` 和 `pending_revision`，不改原始历史，也不从未知记录补造判断。新研究正文待复核时保留上次已确认风险，不能借旧确认冒充新版本已审；普通数值变化不单独创建研究风险转介。风险输入相同的跨日检查复用完成结果，只有真实 forecast 到期等输入变化改变版本。

## 目的与判断单元

Watchlist V1 帮助投资经理了解当前值得注意的机会与风险、近期重要事件及其影响、公开观点和下一观察。优先简单、易用和持续更新；不强制预期差、估值模型、目标价、仓位或自动交易，不新增 Agent 平台。既有深度分析能力保留给适用问题与历史查阅。新闻数量、报告数量、主题数量和 agent 数量不代表研究质量。

研究的基本单元是可修订、可追溯的判断。每次研究根据问题需要连接以下四层，不要求每条新闻都写全套文章：

1. **观察**：发生了什么、信息来自哪里、何时可知，哪些部分只是传闻、媒体转述或主观意见。
2. **机制**：通过什么渠道影响该标的的现金流、风险补偿、供求、流动性或制度约束；影响的规模、期限和反向条件是什么。
3. **定价（问题需要时）**：原先的预期是什么，当前价格可能包含了多少，仍有什么条件未兑现。价格变动本身不能证明原因，也不能证明影响已经充分定价。
4. **决策含义**：方向、适用期限、当前吸引力、风险、把握程度和改判条件。组合行动另外结合实际持仓、集中度、相关性、流动性和实施约束。

业务改善不必然意味着证券便宜；证券值得研究也不自动意味着组合需要加仓。市场隐含预期、分析师预期、舆论关注和资金仓位分别取证。证据不足时保留条件判断，不把未知写成中性结论。

提出投资吸引力判断时，说明收益或风险管理价值从哪里来、适用期限，以及相关的价格、估值、收益率或产品费用与条款等依据，解释为什么补偿得了所承担的风险。依据随标的选择：基金 NAV 点位本身不能判断贵便宜，须结合策略、底层敞口、可比表现与产品条件。适合比较时，结合可比替代资产或持有现金的机会成本；不可比、缺少适用依据时明确限制，不能用“长期看好”替代当前吸引力判断。收益可以来自现金流、风险溢价、估值或预期修订、趋势、套利或组合分散等有依据的来源，不要求每个机会都建立在“市场犯错”上，也不要求每次研究都有目标价、概率或交易建议。

资产层面的判断进一步用于组合时，需要实际持仓和约束：解释它增加了什么收益来源、重复了什么风险暴露，以及流动性、融资、币种、对冲成本和可能损失路径是否可承受。没有这些输入时，保留标的研究结论及组合问题，不推定适当仓位。投资观点由 PM 保留决定与理由，研究员的建议不自动成为已采取的行动。

## 背景、变化与量化如何共同参与判断

变化必须有基准。上次可知状态、同口径历史、此前研究预期、公司指引、分析师共识和价格隐含预期是不同基准，分别保留来源和时点。分清实际经营变化、数据修订、预期修订、价格变化及敞口变化，不能把“增长”直接称为超预期，也不能把更新采集时间称为新的经营变化。

当前水平与变化路径共同决定意义。估值、偿债或流动性约束可能没有变化，却仍决定能否承担风险；增长放缓可能完全符合此前预期。重要更新需交代：相对哪个基准发生什么变化，改变了哪条判断、假设或损失路径，以及下一次什么观察能区分竞争解释。确认原判断也可以有价值，但不能以信息数量、主题数量或更新次数衡量研究进展。

基本面与量化可以各自提出假设、互相验证，也可以合理分歧。按资产和问题选择方法：

| 量化用途 | 对判断的作用与边界 |
| --- | --- |
| 状态与变化测量 | 观察水平、变化速度、波动、分布和可比相对表现；明确数据口径和观察窗口 |
| 假设与规律检验 | 当问题需要且有相应工具与样本时，检验关联、条件表现或预测；描述统计本身不证明规律、因果或可交易优势 |
| 估值与损失路径 | 用有依据的输入分析敏感性、情景和收益风险；主观假设与估计值分别标明，不制造概率或精确点位 |
| 组合影响 | 结合实际敞口、相关性、集中度及可取得的风险贡献检查边际影响；未覆盖的风险保持未知 |

量化证据不必服从基本面叙述，基本面叙述也不能被一个指标机械否定。两者冲突时先检查资产、期限、样本、信息时点与适用条件，保留仍无法解释的分歧及其决策限制，不用固定权重平均出综合分数。当前数值工具提供已实现的序列比较、价格风险及组合风险证据；未执行的统计检验或情景计算不得被叙述为已有量化结论。新方法按具体研究问题引入和验证。研究员也可通过隔离的 Python 工具对本轮已留存数据执行分析，保存问题、数据来源与时点、代码、参数、表格和图表。量化主题沿用方法重算，变更方法时明确说明可比性。工具不向代码进程传递业务数据库、凭据、网络访问或任意宿主文件权限；隔离运行环境不可用时明确报错，不降级到宿主裸执行。描述统计和探索结果不自动视为策略回测或交易授权。隔离环境和部署配置见[量化执行环境](../infra/research-quant/README.md)。

## 谁拥有哪一种状态

| 对象 | 内容与权威来源 | 更新方式 |
| --- | --- | --- |
| 原始证据 | 行情、财报、持仓、公告、资讯、PM 提供材料；保留来源与版本 | 数据系统摄取、修订、撤回，原版本仍可查 |
| 量化证据 | 真实输入、计算口径、共同样本和结果 | 确定性工具计算；模型解释结果，不心算替代数据工具 |
| 标的研究框架 | 对象、主要机制、研究重点、必要资料和反证方向 | 按实际标的维护；框架是询问方式，不是已证实的市场事实 |
| 方法参考与分析 | `research_plan` 保留问题、用户指导及可选方法参考；`research.modules` 按实际问题保存当前分析 | 不要求固定模块或目录覆盖；实际方法引用与版本可追溯，局部复核不刷新其他判断 |
| 当前研究判断 | `research.investment_view`；唯一当前 AI 投资判断 | 按维度修订并保存版本；显式撤回后不恢复旧报告摘要 |
| 决策摘要与重要变化 | `decision_brief` 从当前判断提炼行动含义；`changes` 保存基准、前后变化、机制和决策条件 | 与底稿共同核证、留存版本；摘要绑定观点版本，观点变化但摘要未复核时不能继续显示为当前建议 |
| 事件 | 一次重要观察及其影响、来源、下一观察 | 同一事件追加实质变化；可关联多个主题，不复制事实 |
| 研究问题 | 一个可继续验证的具体问题及支持、反对证据 | 证据判断和跟踪状态分别更新 |
| 持续主题 | 围绕一个长期机制或投资问题组织相关事件、问题、预测和复盘 | 主题有自己的时间线；与全标的动态引用同一记录 |
| PM 投资观点 | 人类原意、作者、日期、版本及关联研究 | 人工直接保存或明确授权助手记录；AI 的复核单独归属 |
| 风控研判 | 当前范围内的研究、价格风险及真实组合输入 | 形成范围内的风险解释和待核实条件，保持输入时点 |
| 预测、复盘、经验 | 可观察主张、对原版本的检验、适用条件与限制 | 保留当时记录；失效经验可以撤回，不继续作为当前方法 |

研究报告的 `summary` 是某轮输出的叙述，不能成为独立续写的当前观点。运行检查时间、判断修订时间和来源可用时间分别保留。安静检查或失败尝试都不刷新旧判断的提出时间。

首次研究中，空白框架、议程或观点表示尚未建立研究，不能据此认定没有值得研究的变化，也不应等待 PM 替研究员指定方向。研究员根据实际标的、敞口和可用证据建立有用的研究任务、初始问题或有条件的判断；资料不足时写明具体问题与所需证据，不强制生成观点或主题。建立有用基线本身可以是研究进展。PM 档案的关注阶段是管理状态，不能被解释为投资上应当观望。

## 统一投资研究工作面

“投资研究”保持连续阅读入口，默认只呈现重要事项、持续主题和适用量化证据。共同的 `research_applicability` 合同根据登记对象、已披露底层/策略、产品机制决定顺序与适用范围：股票、ETF、指数和加密現货以事项与主题为主，公募优先经理、策略和披露，私募优先主题、策略/材料缺口与净值过程，不铺设通用每日新闻栏目。分类名称不证明实际敞口、杠杆、持仓或披露频率；未知保持未知。FCN/期权仍属 Portfolio 私有合约，不转为共享股票。

顶部紧凑显示运行状态、有效研究日期和受控更新入口。暂停、非在投、未配置模型运行环境分别解释；暂停不隐藏历史或确定性图表。当前机会风险长文、底稿全文、问题和证据不再平铺成重复区块，保留在对应事件、主题详情和按需历史档案中。事件保存事实，主题保存持续认识，图表保存可复现计算，风险评估保存当前关注条件，互相引用而不重写多份故事。总览仍优先价格、净值和历史风险特征；PM 投资观点保留独立作者、权限与版本。

近期重要进展默认展开为七个自然日的日期轴，覆盖新闻、政策、技术与具有决策意义的经营、财务或预期变化。每项先呈现标题、重要性、跟进状态、事实简述和投资影响；写投资观点、建立主题与追问直接可见。影响与应对条件、公开观点及依据、研究修订历史分别按需阅读，管理操作不混入证据正文。重要性沿既有 1–5 注意优先级以星标呈现，不另建风险评级。只有报道日期已核实时保留报道日期；事件发生日未知不应抹掉已知报道日，也不能用系统记录时间冒充事实日期。

主题卡展示最新变化（无变化时显示研究问题）及下一验证；完整认识、问题、研究价值、图表与单一时间线按需展开，不重复多套详情。暂停、取消研究与恢复直接可见，取消是保留历史的关闭。人工固定的核心问题与生命周期仍受保护；人工暂停或取消的主题只能由人工明确恢复。

“总览”负责确定性收益、波动、历史回撤和同类比较；“风险监测”承载日度 VaR／ES、事件/基本面风险线索、数值触发、独立风控研判及处理。“风险提示”侧栏保留为同一风险事项的快捷入口。“投资研究”的量化观察可以引用相同数值，解释其投资含义；不在指标页再次铺开事件风险和风控对话。列表名称旁区分已触发风险、风险线索与资料受限；风险线索中，尚无本版本风控判断显示待风控复核，已有判断但证据不足显示已评估待核实，均不冒充已确认风险。

风控范围索引沿用小范围的内联目录。索引超过工具返回上限时，较大的字段返回 `read_research_context(section="scope_index", path=...)` 指针；按同一分区的 `next_offset` 和 `deferred.path` 可完整读取原时点目录，不截断组合事实、标的、报告或必读页清单。目录展开不计为原始风控证据已交付，仍须完成索引列出的标的和组合读取。

`investment_view.opportunities / risks` 是历史底稿中同一判断的可选列表，可同时存在，保存稳定 key、标题、解释、下一观察及引用。它们不再作为独立长文卡片重复铺在默认研究页。省略列表保留原值，显式空列表表达有意清空；旧记录缺失保留未知，不能解释为无风险。`coverage_status` 区分 assessed、limited、not_established，不能代替运行状态或投资方向。有效安静检查保留判断；事件出窗、停止跟进或关闭主题均不解除风险。`DecisionBrief` 仅在适用时解释同一判断，不要求交易指令或目标价。

基础档案复用现有分析、mandate、产品信息和有日期的披露持仓，不要求指定章节。首次缺失时补足回答当前问题所需的业务或产品机制；以后按结构变化和实际披露维护，分别保留业务核查时间、财报期、持仓日期和资料缺口。动态事实继续由原数据层持有。用户研究指导与 AI 工作记录分别维护，指导不是事实。

共享标的身份、Watchlist 分类、经济敞口、管理方式和产品条款各有职责，不以资产类型或分类树自动分派研究章节。公共方法库 `data/research/frameworks.json` 保留经营与现金流、权益聚合、利率信用、供需、管理策略、定价补偿、市场量化、产品实施等可选参考；`research_plan.mode=question_driven`，`modules` 仅包含明确选择的参考，可以为空，也接受目录外的本地方法标识。研究问题决定方法，不要求固定目录覆盖。分类和未知敞口只提供核查线索，不能直接当成持仓事实。直接债券尚未进入主工作面；利率信用方法可用于已经支持的债券 ETF 和基金。

公司预期入口必须先取得共享登记的类型及供应商身份，不能按熟悉的代码补造 ETF 身份。基金持仓的公司资料缺少证券类型标记时，保留类型未确认，不能默认成股票并套用 EPS；已确认公司的观察仍可使用，但须标明未确认敞口的覆盖限制。缺失权重保留未知，不能计为零或宣称完整覆盖。方法参考的增删不会使目录外分析失效；旧分析继续保留原文、日期与来源。

每只标的的 mandate 使用 `guidance` 保存用户自然描述的问题、目标、约束与偏好；背景、机制、问题、资料计划及 `module_focus` 仍是 AI 可更新的工作记录。`PUT /research/instruments/{id}/dossier/mandate` 只接受 `{guidance, expected_revision}`；读取返回 `revision`，首次未保存为 0。服务在与研究发布共用的标的锁下核对版本，冲突返回 409 且不覆盖内容；空指导明确清除额外用户要求。用户指导保留独立作者及更新时间，AI 更新不能重写它或冒充作者。旧人工重点、约束、方法和阅读偏好在读取时确定性合并为指导，AI 自己的 `focus` 不转成用户要求；首次人工保存退出旧的并行人工字段，原版本完整保留。

公共方法正文不复制为新的专属资料。各次运行保留实际选择的 `method_plan`；明确使用的公共方法保留版本，公共方法实质变化只提示相关分析复核，不改变原判断日期或强制所有研究重跑。用户阅读偏好不能隐藏会改变投资决定的风险或变化。决策摘要不是第二套评级，也不自行生成仓位：`basis_view_version_id` 由服务绑定当前观点，读取时派生 `needs_review`；失配的原建议保留原日期，等待明确复核。

分析章节使用自由选择的稳定 `key` 和可选 `title`，不需要在方法库中注册；保存摘要、完整分析、证据覆盖、具体缺口、下一观察、来源与资料日期。`supported / partial / insufficient` 表达证据覆盖，不能当作看多看空或统一评分。未提交的模块保留原内容与检查日期，提交但语义未变的模块只更新自己的检查时间，接受的实际修订保留前版本。模块没有结果表示尚未建立研究，资料空缺不生成虚假数据。新写入统一使用 modules，旧 `fundamental_view / valuation_view` 仅通过集中历史读取映射为带原日期、原版本和原来源的 `prior_analysis`，不再维护平行当前字段或改写历史快照。

可视化使用 `figure_source_ids` 绑定已留存的计算、成份或预期快照，页面从实际值绘图并提供口径与来源。模型不提交任意 HTML、图形坐标或自造指标。研究工作面与阅读模式共用有版本的 dossier；独立数据浏览不冒充报告时点数据，当前总体观点也不从另一份运行摘要拼接。

## 新信息怎样进入持续研究

先检查真实性、相对既有信息的增量，以及对该标的的实际相关性。重要性由可能改变的投资判断决定，不用新闻热度或当天涨跌作唯一筛选。

重要程度、证据可信度、影响期限、市场定价和继续研究的价值分别判断；下面的处理方式是综合这些维度后的安排，不是互斥的金融事实分类。当前影响较小但可能揭示长期机制的信息，可以保留为有明确验证条件的线索。价格已发生反应只是一项观察；“基本反映、反应不足或过度”是带期限和假设的判断，允许暂时无法判断。优先处理可能改变当前决策且具有时效性的未决问题，不要求对每条新闻填满同一份模板。

| 情况 | 处理 |
| --- | --- |
| 重复、无相关性或没有决策意义 | 过滤；不制造用户可见研究动态 |
| 重要但影响短，且没有值得继续验证的剩余问题 | 简述事实与影响；保留来源，不自动建主题 |
| 事件仍有重要且值得继续验证的问题 | 可独立主动跟进并说明下一观察与期限；只有确有长期问题时关联或建立主题 |
| 新信息改变既有长期主题 | 更新对应主题的问题或事件；保留原始机制、反证及判断演变 |
| 出现独立且需要反复检验的长期问题 | 可建立主题，写清研究问题、为何重要、观察与退出条件 |
| 来源修订、撤回或原分析错误 | 触发重新核实并修订/撤回判断；保留原证据和原分析以便复盘 |

例如配售不能因为股价当天已调整就机械关闭。资金成本、稀释、资金用途、资产负债约束和未来资本回报可能仍待验证。反过来，没有可辨别的后续问题，也不应长期保留一个泛泛的“关注配售”主题。

同一地缘事件可以影响能源、航运、通胀和股票贴现率，但各标的要通过实际敞口和机制分别判断。共享原文不意味着共享投资结论；多个 agent 重复引用同一来源不构成独立证实。

新建自动主题须同时有：已取得的具体证据起点、对本标的的传导机制、值得跨多个观察节点验证的未决问题、可区分竞争解释的下一观察和改判/退出条件。沿用 `question / synthesis / priority_reason / next_check / source_ids`，不另造综合评分。服务拒绝缺少基线依据、当前认识或下一验证的新主题，独立复核再判断其具体性与研究价值。技术突破或叙事可以在财务兑现前形成主题，但须区分已证实能力、采用假设、成本/需求传导和反证；“AI增长”“估值”“现金流”等常规分析类别本身不构成持续主题。

市场量化图表按计算合同区分 `observation_domain=market|fundamental|unclassified`，不根据标题关键词归类。内建价格与市场观察按确定方法归类；隔离 Python 分析显式声明用途，并由独立复核核对实际输入和方法。量化观察仅接受市场类图表；公司经营现金流、利润和估值分析放入基本面模块或主题，重要变化进入近期进展。未分类的历史图表仍保留在原始依据，不伪造分类或改写历史记录。

计算来源目录保留按原件合同确定的分类。旧目录缺少分类时，仅对报告实际引用的图表读取分类字段，不展开全部计算。浏览器按标的、原研究版本与来源标识读取 `projection=figure`：SQL 先选绘图结果、单位、样本和必要口径，排除输入序列、输入快照及嵌套计算来源；显示明确标为图表数据，完整依据仍从同一来源入口读取。固定观察中成交量等子指标保留自己的观测日期，不能借用面板截至日。这些只读投影不改写原件，也不改变来源权限或历史版本绑定。

共同样本比较默认展示图表、实际区间与观察数，明细表、计算方法和通用限制通过既有依据入口展开；样本不足与缺值仍在默认面明确呈现。已明确的收益、回撤及超额显示两位小数，相关性显示三位；未知单位的小量级数值不套用此精度，完整计算记录保留原值。

ETF 固定市场观察包含自身 EWMA 波动、回撤、共同区间表现、已披露股票篮子广度、股票 Top 10 权重合计与相关性。`watchlist-observations/v3` 分开研究资料截点、价格日与持仓日期；截点前已知的周末持仓可使用此前完整价格窗口。实际股票分类决定股票篮子，供应商股票数不与包含现金、货币基金和期货的总持仓行数混淆；非股票头寸单独保留，衍生名义敞口未知仍明确披露。相关性描述当前披露股票篮子的历史共振，不能替代历史持仓、风险贡献或全产品杠杆判断；口径、共同样本及缺失处理统一见 [收益序列合同](../apps/watchlist/docs/RETURN_SERIES_CONTRACT.md)。完整输入与表格由同一来源标识分页读取，概览大小不改变计算样本。

波动率以留存的当前值、前次值、变化和真实历史曲线呈现；正文百分比与百分点保留两位，完整原值、计算口径和输入仍可展开读取。页面不重算、不填补缺失值；没有明确单位的指标保留原精度。

## 跟踪生命周期

研究问题的证据状态为 `open / supported / refuted`，跟踪状态另为 `active / paused / closed`。获得支持可能只是验证了中间环节，不能自动退出跟踪；被反驳也不自动等于没有后续需要研究。暂停、关闭及重新开启必须是明确的状态变化，不能由模型默认值或没有新消息推断。

主题暂停后，既有问题可以沿用原 key 和原主题修正证据，并保持或转为暂停／关闭；这不构成恢复研究。新问题、改挂已暂停主题或重新激活问题仍须满足活跃主题约束。

重点主题通常保留 3–5 个，最多十个活跃主题，不凑数量；旧数据不因默认展示调整而批量关闭。主题可以围绕产品、叙事、竞争、经营、风险或量化结构。每轮只预载重要且活跃主题的轻量当前状态；有明确来源关联、真实观察条件到期或人工指定的主题才进入必须复核集合。新材料可产生新的相关性，但须由本轮证据与独立核证证明，不按标题猜测。未提交主题保留原判断日期，不能标成本轮已复核。

事件独立使用 `follow_up=watch|none|resolved`：watch 必须有具体下一观察，可以没有主题；none 表示不再主动研究，不表示风险已解除；resolved 须有支持解决的证据。服务端从明确开始主动跟进起设置默认 30 个自然日期限；旧记录缺少开始时间或跟踪状态时保留未知，不补造历史日期。到期触发收尾研究，成功后可附原因停止或明确延至下一节点；失败保留 watch 和到期待复核。重复运行与转载不续期，旧消息不重新激活。PM 固定、明确未来观察节点、重大未结风险保护原安排；Agent 不控制固定。主题接管须链接原事件及依据并说明原因。

每个新重要事件有 1–5 注意优先级及具体理由；3–5 进入主时间线，1–2 保留为背景材料。评分不是收益概率、交易评级或风险严重度，不覆盖 confidence、impact_level、urgency；历史缺分显示未评估。默认最近七个自然日含当日，使用应用显示时区，以核实的事件或进展日期优先、发布日期其次。未知日期不造今天，晚到旧材料标记补录，例行检查、文字修正、评分与延期不刷新事实日期；仍在跟进与历史分别按需读取。展示窗口不截断成功覆盖位置之后的采集范围。

事件展开分别显示事实/意见/传闻、影响路径、带发布者和日期的公开观点、留存确定性计算的市场反应、下一观察和来源。转载同源不构成共识，发行人宣传不独占市场观点；未读取原文不标为已读。市场反应保留实际窗口、基准、币种、尚待观察与其他干扰，不从价格推断因果。

关闭的理由包括：关键问题已得到足够回答、原机制已不适用、已无剩余决策意义，或研究范围明确改变。关闭保留结论、理由和历史。仅仅到期、价格反应、暂无新闻或证据不足都不能单独证明问题已经解决。暂停适合主动停止研究但仍可能恢复的事项。

自动研究可维护普通主题，包括用户提出的主题；提出来源与是否固定分别保存。用户明确固定的主题，其核心问题和生命周期保留人工控制。用户主动暂停或关闭时另外保存生命周期归属，即使未固定也只能由用户恢复；研究员可纠正原资料，但不能擅自重新开始跟踪。历史记录按最近一次状态变更的责任人识别归属。

## 每轮检查与长期连续性

每轮先冻结 `research_working_sets`：对象与权限、信息截止、上次有效基线、持续跟踪事项及版本、重要主题候选与受影响集合、触发原因及直接依赖的来源。生成、独立核证和发布沿用同一清单。默认只读 `follow_up=watch` 的事项和重要活跃主题，仍有效风险约束另行保留。历史正文、全部事件修订、关闭或暂停主题、旧工具输出不自动进入工作集。

原件按来源或确切历史版本读取。显式历史读取单独绑定本轮引用及原时点，不把整段历史复制回来，也不把读取当作核证。来源更正、撤回仍检查当前判断对旧来源的直接依赖。未选中表示本轮未复核，不表示不存在、已解决或风险解除。部分发布在原主体、租约和版本锁下从完整当前底稿稀疏合并，保留未涉及内容和未知旧字段，不用缩小上下文绕过整体 CAS。

确定性扫描与模型尝试分开。`research_monitor_state` 保存扫描位置、待处理变化、尝试版本和成功应用位置；失败或暂停不消耗待处理信息，只有实际发布才确认对应冻结变化。跨日、部署、打开页面和普通价格、NAV 变化不触发整份研究。普通数值进入图表，实际资料到达或更正、明确条件到期和真实风险规则才构成研究候选。无变化仅推进无模型扫描，不改旧判断日期。

实际模型用量按调用及生成、核证阶段记录供应商返回的未缓存输入、缓存读取、缓存写入和输出 token；同一次请求的流式回执与最终回执不重复求和，输出已包含推理 token。中断或供应商未回报标为 partial/unknown，不写成零，也不从耗时推算费用。Watchlist 和 Briefing 留存在原任务 JSON；截图分析沿用结构化日志并绑定批次和 attempt。临时采集文件有界且随调用清理，不记录提示词、原文或凭据；记录失败不能改写原任务结果。

不同变化分开处理：

- 新的事实、反证、实现结果或观察窗口，可能要求更新具体问题、预测、判断或框架。
- 有研究进展但没有新的投资含义，可以只更新底稿。
- 已检查且没有实质变化，保留原判断和日期；不重复追加文章。
- 来源缺失、日期不明、搜索失败或资料尚未披露，记录具体缺口及它限制的判断。
- 运行失败保留最后完成结果和失败状态，不冒充一次有效的安静检查。

更新覆盖以最后成功的研究截止为基准，失败尝试不能消耗尚未处理的信息。运行分别保留资料准备、草稿生成、独立核证和发布阶段；可识别的暂时性服务故障允许有限重试，草稿和核证检查点沿用原信息截止与证据。重试仍须验证当前权限和底稿版本，不能覆盖研究期间产生的新判断；确定性的输入或协议错误需修复后再恢复。批量更新通过正常发布路径执行，不直接修改报告或伪造完成状态。

已核证草稿因发布校验失败需要重新核证时，必须显式请求 `queue_retry(..., manual=True, recheck_review=True)`；仅跳过该请求之前的发布检查点，保留同一已接受草稿、冻结输入、截止时间及完整核证和失败历史。新核证检查点仍按正常恢复流程复用，普通手动和自动重试的检查点复用行为不变。

研究提交工具在原始参数入口递归拒绝未知或错层字段，不能静默丢弃内容。工具声明对每层提交模型明确禁止额外字段，与运行时严格校验相同；自由字典键不受此模型字段规则影响。一次返回该次提交的全部格式错误及各错误所属对象的合法字段和必填字段，不回显提交正文。独立核证收据同样按冻结 schema 一次汇总各处结构错误，错误路径中的未知自由键脱敏；联合类型只提示实际出错路径、规则与同一 schema 的分支位置，不把互斥分支的失败变成同时必填要求。不自动补空字段或接受局部提交，修正须保留有效内容并重提完整对象。`reflection` 位于 `reviews[]`，`decision_brief` 位于 `reviews[].research`，事件 `market_reaction` 使用 `figure_source_ids`；不得在修正时把原本正确的字段搬到错误层级。助手保留完整结果外壳，只重提实际变化的研究字段，不复制整份历史底稿。历史档案读取和正式金融、来源、时间及授权校验不因这一提交约束改变。

研究助手、标的研究和风控请求先在数据库持久排队，由独立 `research-worker` 执行；API 启动不再清空或判失败，API 不持有模型进程。每个任务有执行序号、owner、30 秒心跳及默认 300 秒租约；所有 worker、手动、每日调度和初始化批次共用数据库并发额度，默认 1。租约到期先使旧执行凭证失效，再在最多三次总尝试内恢复。正常停机终止整个 Harness 进程组，输入、草稿、核证检查点和失败类别保留；业务发布与完成状态在同一事务提交，已完成结果不会因 worker 来不及确认而重复发布。

队列只保存绑定原主体、run 和 attempt 的短期委托凭证，最长 24 小时且不超过原登录或父委托有效期；不保存登录令牌，也不向页面输出队列凭证。领取及阶段切换重新验证原主体，撤权或过期明确失败。API 保存请求后、派发持久化前若中断，无有效队列的旧请求经过一个租约窗口才可收口：全局暂停时保留为 paused，正常执行环境标记 DispatchInterrupted；不会抢占刚提交的请求或重放已完成结果。

阶段结束时使用该阶段委托自己的凭证撤销自身；队列父委托不能借服务证明代撤子委托。父委托仍由队列生命周期单独收口，父撤销或失效也会使全部子委托失效。签发阶段凭证与撤销自身分别遵守 Home 现有授权合同，不扩大代理的身份权限。

助手对话查询只返回原答复、运行状态和证据目录，打开一条依据时再按原 run/source 读取冻结原件。页面中的大型原件分段渲染并可下载完整内容，避免把多年原始输入一次塞入浏览器正文；分段只改变展示，不删除观察或改写历史依据。

回答中的引用也加入轻量证据目录，但只接受该运行实际绑定的来源或研究原版本。`citation_only` 与真实工具回执明确分开：引用不证明助手已完整读取或独立核验。未绑定的编号不查询全局资料库，也不以当前内容补造历史引用。普通数值原件、当时标的快照、原文版本和研究判断分别保留原身份与时点。

自动标的研究和风控的结构化提交经服务端验收并持久化即构成本阶段完成；模型补充结束语失败不会撤销已受理结果。助手显式授权团队发布时仍先保留完整私人答复，不能因草稿已受理而截断正文。研究草稿仍须独立核证。风控已受理、尚未发布时发生执行中断，保留原 attempt 的产物并仅恢复发布：重新授权、沿冻结输入执行原范围、来源、版本和风险状态校验；不启动新模型，也不把旧已读回执移作新会话的阅读证明。未受理提交的正常进程退出明确记录 `NoAcceptedSubmission`。普通 MCP 外层截止为 180 秒，HTTP 请求为 150 秒；受控量化仍遵守其独立执行截止，不为超时盲目重发写操作。

标的研究与风控的自动恢复共用原运行、原发起人及最多三次总尝试，分别等待至少 60 秒、300 秒；已经准备好的风控快照不在重试中换成后来资料。恢复前核对当前写权限或组合访问，完成时再次解析身份并检查发布权限；用户降为只读或服务研究权限撤回均不能继续发布共同判断。失败不关闭既有风险，也不消耗新的成功覆盖位置。

研究生成和独立核证分别拥有 30 分钟截止，包含助手显式授权团队发布；生成完成先保留绑定草稿和私人答复，再重新验证原发起人授权并进入核证。普通私聊没有受理草稿时不启动核证或发布。助手发布中遇到 worker 中断，可沿同一 run 的草稿、私人答复与核证检查点分别恢复核证或仅恢复事务发布，不重复生成正文；最终仍检查原权限、范围和版本。核证自身失败或超时则保留私人答复为已完成，明确记录 `research_publication=failed` 和 `automatic_retry=false`，不自动再次付费核证；正文中的发布措辞不能替代实际发布状态，也没有新增助手同 run 重试发布入口。

超时后终止整个 Harness 进程组，五秒宽限后强制清理仍存活的后代，不能仅以父 shell 退出认定已停止。Watchlist、Portfolio 截图分析和 Briefing 共用 `studio_runtime.processes` 清理；父进程回收也有五秒上限，清理失败只记录异常类别并保留原始失败，不能无限等待输出管道。自动标的研究的核证到截止时保留已持久化的绑定草稿及输入快照，可在上述预算内只恢复核证；未形成草稿的生成超时不自动重跑。生成与核证的模型单次输出上限均为 65536，普通问答和风控仍为 32768；上限或供应商内容过滤会保留明确失败类别，不按暂时性故障自动重试。核证原件读取与完整收据校验不因额度调整而减少。

复核同时检查原判断的推理是否成立。发现旧事实错误或无依据的推断，本身就是应记录的研究变化，不需要等待新新闻或行情；仅修订受影响的判断，保留原版本。没有新证据可以保留一个未决问题，不能成为继续保留已发现错误的理由。

自动复核回执列出实际检查的原记录 ID。它说明进行了哪些检查，不能单凭“已复核”证明结论正确。未检查的项目保持原来的检查时间。每日时钟是检查机会，不是观点更新配额；基金月度净值、不同市场休市和 BTC 全天交易分别处理。

先前取得的文档仍是需要跟踪的对象。修订版本即使删掉原来的关键词或实体标签，也不能因搜索不再命中而漏检。比较原文版本与状态，用新证据重新评估，不能将修订后的正文回填为过去已知。这项检查针对共享原文库已取得的新版本，不意味着自动逐网址重新抓取全部历史链接。

## 数据足够与否，取决于研究问题

“工具可调用”“有报价”“有一份报告”和“足以支持当前判断”是不同结论。已绑定 FMP 身份的股票可先读取财报目录，按报表期、类型和财期选择季度或年度三表原始科目；页面的年度利润表简版不限制这条研究通路。目录、报表与科目缺失分别保留，不保证供应商对所有公司或市场都有完整覆盖。其他来源及资产仍按实际已取得资料研究，无来源的补齐数值不构成数据完善。

| 研究对象 | 需要按问题取得的主要证据 | 不能推断的事项 |
| --- | --- | --- |
| 公司 | 业务与经营指标、三表、资本配置、融资结构、同口径预期与估值 | 只凭收入/利润增长判断现金流和资产质量 |
| 股票 ETF / 指数 | 实际成份与权重、集中度、成份业务、预期覆盖、估值与跟踪方式 | 把成份公司 EPS 相加当 ETF EPS；用另一只基金替代实际持仓 |
| 债券/商品等 ETF 或基金载体 | 实际底层、久期/信用/供求机制、货币、对冲、展期或基差等已取得资料 | 给所有 ETF 套公司盈利框架 |
| 公募/私募基金 | 正确 NAV 类型与频率、基准及共同样本、持仓披露期、策略与条款 | 从平滑净值推断没有杠杆、流动性好或持仓安全 |
| BTC 现货 | 已完成行情、供给与网络/资金/杠杆等确实取得的数据、市场制度 | 从价格推断链上活动；套股票交易日和公司估值 |
| 组合 | 真实持仓、完整分母、币种、敞口、可用风险贡献和流动性约束 | 把 Watchlist 成员当持仓，或把权重当风险贡献 |

单位、币种、期间、复权/NAV 类型、信息时点、共同样本、覆盖率都属于数值结论的一部分。分析师覆盖进入/退出不等于预期上修/下修；零覆盖不能生成一个“盈利下降 100%”的研究事实。历史重算的 Regime/风险快照如不能重建当时可知信息，须作为当前分析工具使用，不伪装为历史预测。

共享资讯先检索再读取原始版本；辅助搜索用于实际缺口，检索结果不是已核实原文。搜索通道不可用需要保留缺口，已知官方原文仍可以定向读取；不能据此宣布没有重要新信息。

`read_stored_market_data` 提供项目已支持的财务、预期、ETF、宏观与商品数据合同目录，以及指定数据集、标识、日期范围的分页读取。目录标为未检查覆盖，实际读取才说明是否取得记录；所有读取绑定本轮信息截止。标准财务科目可支撑对应口径的分析，缺少财报原文或附注只限制依赖它的判断，不阻断其余研究。原始字段、单位、观察期和来源保留，不能因统一工具入口而假定各供应商口径相同。

## 人与 agent、研究与风控

PM 可以随时提出假设、记录判断、调整研究问题或要求研究助手继续调查。主观观点允许尚未验证，但必须归属清楚。AI 既不能把自己的想法冒充 PM 原意，也不能把 PM 的确信当作外部事实；分歧应转化为具体的证据需求、情景或改判条件。

新观点必须保存形成判断时的背景，系统预填的研究背景与用户判断分别归属；主题、事件、图表入口绑定原始版本、来源与时点，直接保存不依赖助手对话。单独新增可由用户填写背景，不强制先搜索。旧观点缺背景时明确展示“当时背景未记录”，不得用今天的资料补造当时依据。当前总体投资观点由用户明确选择某一观点版本；最新记录、补充判断、复盘和经验不自动替代它。删除已选观点会清除当前选择，但保留选择和观点修订历史。

从投资观点发起讨论时，助手绑定用户所选的 `pm:<note_id>:<revision>` 及其原来源；页面打开后产生的新版本不替代该判断。缺失、错标的或无权访问的引用在入队前拒绝，不建立没有原判断依据的复盘。

原观点应能回到当时作者、版本和引用的证据。修订后的 PM 观点与之前的判断分别保留，事后回忆不得被写成事前预测。
PM 档案中的研究负责人和维护人不等于观点作者；旧记录没有作者归属时明确保留未知，不能据此补造作者。旧引用没有单独冻结原文时，按已保存运行和明确引用读取，并展示这项局限。

风控需要看到风险事项背后的当前研究条件、相关 PM 观点及未决问题，并结合实际持仓。它区分标的风险、组合暴露、已量化的风险贡献和未知事项。研究认为长期向上与风控认为短期脆弱可以同时成立，应解释期限和约束，不能机械投票出买卖方向。

价格规则摘要保留带符号的 `value_pct`，并以 `metric` 区分滚动收益与当前回撤；正的 `limit_pct` 表示损失幅度，实际触发条件为 `value_pct <= trigger_at_or_below_pct`，其中触发点为负的限值。`loss_magnitude_pct=max(0,-value_pct)` 只描述该观察窗口的损失幅度，正收益对应零损失，缺失仍为未知。这些复核线不是可消耗的风险预算，也不是从当前价格还能下跌的比例；正收益和零触发均不能推导低风险。新摘要使用合同版本 2，旧冻结结果保持原样。月度证据分别提供 `latest_completed_observed_month` 与 `latest_negative_completed_observed_month`，后者仅在同一份展示月表内寻找最近负收益完整观察月，不能冒充最近完整月。两者保留实际观察日期、状态与限制；缺月不能推出连续性，最新观察月不可用时不以更早的负月替补该读数，最新月内收益与滚动窗口另行解释。

研究事件的跟进安排与风险权威状态分离：停止研究、到期或无新消息不能解除风险。新风险线索保留稳定关联并标记待复核，独立风险研判失败不撤回已合法发布的研究；重复线索更新原事项。既有活跃风险保守保留。同一事件版本的相同风控判断在不同范围内只追加各自运行回执，不改写共享风险事实；市场、研究、PM 操作或风险判断的实际变化才改变复核输入，避免多个范围互相触发重复运行。

重要风险读取分为 `last_assessed_snapshot` 与 `pending_revision`。新版本待复核时保留最后已确认且未解除的判断与原日期，新正文不得借旧评估冒充确认。旧来源撤回时明确原依据失效并保留历史。重大、有原文依据且有具体限时决策条件的新事项独立标为“重大待核实”。普通波动、一般资料不足和任务失败不占首页重要风险入口。已读、研究暂停、无新新闻和价格反弹均不解除风险。

首页保留四个入口，下方默认最多三个短风险链接，有更多重要事项时显示数量并可进入完整范围，点击转到对应标的或组合。空列表只表示没有符合入口条件的提示，不表示全部资产无风险；暂停状态诚实提示。

团队风控对本轮绑定的每条待复核研究上报必须留下结论和原因；证据不足可以明确保留待核实。缺少回执不能完成研判。手工发起的具名 Watchlist 复核可以覆盖成员；Portfolio 私有暴露评估不能改变或代替共享风险判断。自动复核覆盖所有当前在投且有效的标的，未覆盖范围不得宣称已更新。

自动风控比较事项的真实条件与处理状态、研究转介版本及独立判断，不以行情日期、NAV 或读模型重算时间购买新一轮研判。无事项时不建立空任务。手工阅读中的数据过时提示和发布的一致性校验仍使用完整物理数据版本；自动准入的小快照不能代替它们。原运行的独立评估结果纳入自身已处理快照，避免发布本身再次触发研判。

事件的 `impact_level`（影响程度）、`urgency`（复核时效）和 `confidence`（证据可信度）分别保存。风险渠道、传导机制与行动条件进入研究和风控读取；未评估的程度与时效保持未知，不默认高风险。重大影响须解释机制，立即复核须给出具体决策条件；已有事项类别继续采用原有 `severity` 合同。

首页 `/api/risk/alerts` 读取共享已发布事件的最后有效风控判断和当前待核实变化：重大且仍有效的已确认风险继续显示其原评估时间，新版本不能借用旧评估背书；有原文依据及具体紧迫决策条件的重大新线索独立显示“重大待核实”。普通未核实事项、纯机会和已解除事项不占入口。来源团队先过滤，再统计与分页（默认 3 项、每页最多 10 项）；用户明确授权发布的共享事件可入选，私人答复与组合材料不读取。来源撤回时明确提示原依据失效，保留审计历史。接口只读，不启动研究或另存一份风险状态。

同类比较和研究资料按需分页读取，保留完整共同样本和来源。数值概览保留实际计算结果；完整序列、共同日期和原始输入通过同一个计算来源继续读取，续读不重算、不改日期窗口、不替换数据版本。大工具包被截断不能被当作研究员看过全部资料。可用的 Regime 状态仅在已绑定范围和时点内解释，没有取得时不得声称已综合宏观状态。

一次研究提交校验中，相同原文版本和相同位置的计算原件只读取一次，仍逐引用检查归属、来源资格与截止时间；不同版本、标的或共享授权边界不合并。复用范围仅限本次请求，不跨请求保存权限或内容缓存。同一标的的事件校验复用本次市场时钟和一次取得的当前事项集合，金融和证据门槛不变。

助手页面的“当时证据快照”按原运行和 `source_id` 读取留存原件；Portfolio 通过同源代理转发当前用户身份，由 Watchlist 校验原对话、组合权限与来源绑定。大原件在浏览器分段显示并可完整下载，不向此快照接口另传工具分页参数，也不以当前资料补造历史证据。

关联 Portfolio 的私人助手使用 `read_portfolio_holdings`，首次读取保存同一有效日的组合持仓与规范账户账本。概览优先展示账户总数、可读名称、币种、带符号的已结算现金和待结算余额、有效日期及逐项缺失标记；估值或 FX 不完整不抹掉可读取的原币余额。零余额是已知事实，缺失保留 `null`，不能用组合 NAV 合计反推现成账户余额。同币种现金净额／毛额只汇总各账户的已结算与待结算余额，不代表证券、衍生品或券商购买力；完全抵销不等于收益历史缺失，也不意味着全部风险为零。Forward RC 继续引用 Portfolio 原始模型状态、窗口覆盖及错误原因，零方差时不制造 RC。

同一运行重复读取概览复用首次留存的 `source_id`；全部账户、完整持仓、长序列、所选对象和风险明细通过同一工具的分区、`next_offset` 与 `deferred.path` 继续读取，单页保持在 Harness 载荷范围内。账户很多时也明确给出总数和账户分区入口，不静默截行。每页沿用原运行及组合权限，不能跨组合或跨运行读取；续读不再查询实时账户或行情，不创建主题、重跑分析或发布共享研究。已完成运行重开仍保留原回复和原证据；旧证据未保存的事实不会以当前数据补造。`read_portfolio_risk` 专用于自动风控运行，私人对话的风险事实从 `read_portfolio_holdings(section="risk", source_id=...)` 读取；该分区只包含本轮实际留存的风险依据，额外的 `risk_context` 仅在原风险页面读取，缺失不表示已读完所有风险模块。

风控事项页只在同一原页内复用完全相同的依据：展示来源与完整来源中的重复结构，以及同一事项前后快照中整份原始内容相同的来源，通过 `same_as_path` 明确指向保留的完整位置。来源身份与版本保留；原始正文或数值不同，即使来源 ID 相同也不合并。小型元信息保留直接展示。引用不算原件已读，目标的全部续页与延后分支仍须完整交付；冻结快照、不同历史原件与范围权限不变。

风控准备沿用研究的权限和当前版本选择，从数据库投影当前观点、有效问题与预测所需字段，常规读取不载入整份研究底稿及其重复历史；前次对照只读取同范围最近完成任务的冻结输入。选中字段需要特殊字符恢复时，仍从原始 JSON 精确还原。研究原件、风险事项及历史版本继续完整保留，所需原件的读取门槛和来源资格不变。

风控任务在没有已受理发布检查点时重试会启动新的助手会话，清除上一会话的已读页回执和未发布提交，重新完整读取本轮资料；冻结输入、前次快照、截止时点、发起人和失败历史保留，不重新准备或替换证据。

资讯检索先返回可续读的结果目录，完整覆盖说明与原文分别分页；零匹配须明确呈现。目录命中不等于已读原文，后续读取绑定原查询时点和文档版本。提交引用有误时，指出具体无效标识，保留其他有效引用。事实核证只能依据实际提供的原文、计算或明确标注范围的快照概览补正引用；资料存在于库中不等于本轮已核实。价格变化本身不能证明预期已充分计价，缺少适用估值或预期证据时须保留条件与未知。

## 复盘、学习与评估

复盘围绕原始预测或判断版本进行，分别回答：观察到了什么、机制是否得到支持、原定价判断怎样、还有哪些解释、当时可知信息下哪里做得不足。收益结果不能单独证明决策好坏；一次成功不能生成普适交易规律。

经验写明适用情形和限制，可由 agent 随证据更新或撤回。局部经验不自动改写所有标的框架；当多次反证表明框架遗漏了关键变量，应明确修订框架及适用范围，并保留原版本。人类随时可以介入。系统不会为了每日“学习”产生新规则、无根据阈值或评分。

评估区分三层：

1. **合同正确性**：原文与时点、数值可比性、当前/历史、生命周期、权限和实际读写行为。用真实故障和代表性跨资产情景做回归。
2. **研究质量**：相关性、机制、定价、反证、可检验性、行动意义和诚实的覆盖限制。独立事实核证是其中一环，不能证明因果或投资收益。
3. **前瞻决策价值**：随着真实观察窗口到来，审视遗漏的重要变化、错误更新、迟到的修订、无意义跟踪及原判断结果。样本及标准随问题和期限选择，不用统一命中率或短期收益给整个系统盖章。

当前采用一个负责研究的 agent 加独立事实核证，并使用确定性数据工具和版本化档案维持连续性。多研究员协作是后续可选增强；引入前应证明它改善特定问题的证据或判断质量，而不是以讨论规模代替上述基础。

工具响应在 HTTP 服务端完成分页，再送入 MCP；不先传送整个上下文或计算包再在模型侧截取。计算结果按本轮 `source_id` 续读，保留同一来源版本、完整样本和计算口径，单页不超过 48 KB。风险概览、事项正文和当前研究判断来自 `read_context_json` 的决策投影；原始计算输入、逐点序列和原文仍留在冻结快照，通过 `read_risk_evidence(snapshot, path, offset)` 按论证需要读取。片段内容摘要只用于识别前后快照中相同的原件，读取地址变化不算资料变化。原文引用不是已读证明，亦不能根据未读取断言没有风险。

数值、共同样本比较及隔离 Python 产物的原件按 `run_id + source_id` 写入独立的 `research_run_evidence`，同一事务在小运行元信息上检查状态与 attempt。这些工具追加计算时不读取、反序列化或重写无关的大型 `context_json`；小目录与比较回执由原件元信息派生。0068 仅创建新表，不搬移或改写历史原件。历史原件仍按原运行、来源及明确历史版本读取；旧 JSON 的特殊字符保持精确，不用今天的同名来源替换过去版本。

新的 notebook 继承和量化输入保留来源位置引用，不再嵌套复制先前计算的全部输入树；目录与轻量结果说明不是原件本身。量化只解析已在本轮来源容器绑定的输入，按指定历史版本使用独立的命名空间与截止时点。引用解析检查来源身份、标的、团队与组合权限；已授权共享档案中的确切来源保持原有团队可读语义，不因原计算出自同团队私人助手而丢失。任意用户 JSON 或量化结果 `data` 内的同名字段不会成为跨运行读取权限。事实核证子进程通过本轮 API 取得草稿实际引用的原件，嵌套量化输入按需续读，不依赖数据库连接或重新计算。

风险提交前的必读覆盖包括范围内全部标的概览，以及当前和前次非空的风险事项、研究判断正文。超长正文仍须完整分页读取；已经提供计算结果、口径、样本覆盖和限制的数值证据，不再要求模型递归遍历全部原始点。交付收据和已接受结果按 `run_id + attempt` 保存在独立的小状态表中，读取一页不会重写整份冻结上下文。新尝试或重新准备输入清除旧覆盖状态；旧尝试不能提交或覆盖当前结果。组合风险模块也在服务端选取和分页，集中度保留原分类/范围与来源续读，其他大型模块按返回的路径续读。

研究生成与独立核证均运行在固定版本的 DeepSeek Harness 中，使用原生流式模型请求、工具循环及自动上下文压缩。压缩保留任务、判断和待办的工作记忆，原始证据仍按来源、版本及信息截止分页复读。研究生成可按需获取资料；核证 agent 只读取本轮固定的草稿、历史判断与原始证据，提交绑定草稿的核证收据，不联网补造依据或直接发布。概览先提供简明判定合同和绑定对象索引；`submit_review_receipts` 的工具输入声明直接采用同一冻结包的完整 `response_schema`，包含必填字段、绑定身份和纠正分支，不维护另一套模型。具体字段的可选纠正格式仍可通过既有分页工具按路径定位，不要求接受原提案前遍历全部纠正分支。草稿与必需覆盖信息仍须完整交付，相关旧判断和引用原件须有实质内容读取；目录或压缩摘要不能代替原文。提交始终执行完整响应 schema 与绑定草稿校验；应用在核证完成后统一校验来源、权限与底稿版本并发布。

核证收据提交前即复用发布阶段的事件和公开观点来源／发布时间检查，保留相同的原文资格、截止时点、时区及日期精度；引用修订使日期失去依据时，返回具体事件键和字段供同一核证会话修正，不自动推断日期或改写来源。来源的已读父页若完整内联交付非延后的实质子树，该子树同样算作已交付内容；目录、标量元信息及未实际交付的延后分支不能替代正文。长文按待核证论点读取相关片段，回执保留来源及已有版本、路径、字符范围、长度和单页是否交付完整文本值，不把片段标为全文已读。该门槛只证明实际接触原文，不证明论点有支持；不按字数、标点或句法推断充分性。核证员须判断片段与上下文是否足够，不足则补读或修正结论。明确的空预期对照须连同比较时点、覆盖、限制和全部结果数组交付，不能因没有结果行而要求读取不存在的内容；空数组不自动等于预期不变，零覆盖或不可比仍保留未知。草稿、必要覆盖说明和相关旧判断的完整交付门槛不变。

自动研究与受控初始化默认一次运行一个标的；`INVESTMENT_STUDIO_WATCHLIST_RESEARCH_WORKER_CONCURRENCY` 可在 1–4 之间配置，初始化 CLI 的 `--workers` 仅控制提交与等待数，不绕过数据库执行额度。共享小内存主机保持 1，实测资源充足再提高。单项的生成／独立核证、同一标的去重与每个范围先完成研究再交风控的顺序不变；独立 worker 停机时终止模型进程并保留恢复状态，不继续领取队列。运行权限检查只读身份与历史组合范围投影；选读上下文、单个计算与底稿不载入无关的整个研究快照。

UI／自动研究首次缺少有效投资观点时，以及受控初始化明确补齐资料时，准备阶段绑定 `initialization`：从原始 `input_snapshot_cutoff` 向前七天检索相关消息，并核对最新官方公告、必要基础资料、PM 观点、既有研究和适用量化。更早的必要背景与晚收材料保留原日期；之后补充网页推进知识截止时间不会改写初始化窗口。资料缺失记录具体限制，真实零结果可接受，不按新闻条数验收。独立核证同时检查该窗口、查询相关性和 coverage 声明。CLI `complete` 仅表示所选标的已发布且观点可读，另列 `evidence_coverage` 查询／缺口以供逐标的核对，不能据观点非空或搜索附带的 instrument_id 宣称资料初始化完整。

核证进程在首个页面前退出时，仅留存已知运行器类别、HTTP 状态及系统错误码等诊断信号，不保存原始 stderr 或据未知退出自动放宽重试。已持久化草稿的人工恢复仍复用原始资料与截止时间，重新检查授权并正常完成独立核证。显式重新核证时，`acquisition.review_recheck` 传入上次发布错误供修正定位；这是恢复诊断，不是投资证据，也不授权改写来源日期或结果。

## 版本收口与持续评估

版本固定四个研究入口的职责、证据与判断归属、时间和版本规则、跟踪生命周期及发布边界；标的观点、观察指标和具体研究方法仍按证据修订。新结构或新模型应解决实际研究问题，不因增加报告、分类或 agent 而扩展。

稳定版本须对应明确的代码与配置基线，并用实际覆盖范围内的代表性案例验证数据、计算、研究、发布和人工介入。验收关注：基本面改善但价格吸引力下降能否分辨；基本面与量化冲突能否保留和核查；没有新消息时价格或组合风险变化能否进入判断；弱线索能否以具体问题跟进；无变化、缺数据及运行失败能否正确区分；反证、结束跟踪和 PM 原观点能否保留演变过程。按适用案例检验，不要求每个标的展示同一套输出。

工程测试证明的是已测试的行为与边界。尚未成功执行的数据采集、搜索、模型调用或发布不能算已验收；当前记录为空或失败，也不能被解释为没有值得研究的机会或风险。真实研究产出的相关性、数值和推理连贯性需要单独审阅。长期决策价值在发布后持续观察，不以短期盈利、统一命中率或未到期预测作为定版的前置条件。
